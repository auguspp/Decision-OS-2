# 仓库、命名与首批接线合同

范围：实施基线 v0.1 的工程决定；实际代码/接口尚须在各自任务交付。依据最终设计第5—8、14、18—20章；本文件不成为第二份产品设计。[实施基线](../implementation-baseline.md)

<a id="naming"></a>
## 1. 命名先区分不同对象

| 类别 | 规则 |
|---|---|
| 产品/仓库 | 显示名Decision OS 2.0；仓库保持 `auguspp/Decision-OS-2`，不再创建建议名称的新代码仓 |
| Python | 分发名 `decision-os-2`，import `decision_kernel`，命令 `decision-os`；模块/函数snake_case、类型PascalCase。名字沿用不承诺旧API/schema |
| 文档/工作流 | 新文件统一kebab-case；根README/AGENTS/WORKING-PROTOCOLS及GitHub标准模板保留约定拼写 |
| 机器ID | 稳定ASCII标识，不以公司简称、中文标题、日期单独充当唯一身份；ID创建与重试复用分开 |
| 来源/实体 | 证券≠公司；行业≠产品；产品规格/地区/税费/计量不同不可混成一个价格；provider不进入实体本体ID |
| 原文件与显示名 | 原件中文/大小写/字节保留；存储路径由安全生成的ID管理，原名仅作元数据，不让上传路径决定写位置 |
| 版本 | 软件版本、schema、研究修订、方法、来源内容、提取器、计算规则各自维护；不用一个“v2”表达所有变化 |
| 时间 | 时区明确；显示Asia/Singapore，实际记录保留来源时区/精度；报告期、披露日期、取得时间不互相替代 |
| 分支/PR | `type/<issue>-purpose` 与 `type(scope): 改变`；施工号不写进永久模块名 |

日期只有日期就保存日期，不编午夜；数据用途不需要的时钟不强制填。研究依赖明确版本，查询“最新”不得在冻结引用中悄悄变化。

<a id="topology"></a>
## 2. 目录按责任建立，不先铺空壳

实际首批文档位于本仓现有路径；#5从 `pyproject.toml`、实际依赖锁和 `src/decision_kernel/` 最小包开始。后续责任对应默认归属：

| 责任 | 默认代码归属 | 外部效果/依赖边界 |
|---|---|---|
| 稳定值、版本与必要约束 | `domain/` | 不依赖网络、GitHub或提示词执行 |
| 确定性分析/研究政策 | `methods/`、按领域纯函数 | 不偷取行情或修改研究/Decision |
| 纯解析与观察变换 | `observations/` | 使用已取得输入，不借publisher工具 |
| 接收、研究提交、读取和交付用例 | `application/` | 拥有本次操作、资源/状态/预算与必要窄端口 |
| 来源、Git、文件/数据库实现 | `infrastructure/` | 实现明确I/O边界，不自行决定研究策略 |
| CLI、宿主和组合根 | `interfaces/` | 显式接线，不变成万能调度器 |
| 测试/样例 | `tests/`按实际合同归组，`tests/fixtures/` | 合成/获准样例与真实运行数据分开 |
| 工程和方法文档 | `docs/engineering/`、`docs/architecture/`及未来实际方法路径 | 不复制当前任务状态 |

没有真实消费者就不建目录/接口；一次调用不必穿过六层。跨模块共享先证明同一语义与多个消费者，再提到正确owner，不用`utils.py`/万能contracts桶承接业务杂物。CLI/包资源/工作流路径/动态引用属于真实消费者，移动前查，不能靠跑坏CI发现全部依赖。

<a id="authority-map"></a>
## 3. 每类数据只有一个写入责任

| 对象 | 权威写入者 | 非权威副本 |
|---|---|---|
| 代码/规则/方法配置 | 本仓main经PR | 安装包/阅读镜像 |
| 来源原件、摘录、数据集版本 | 已获准来源接收owner | 可重建索引、有限导出 |
| 研究修订及有范围的当前指针 | 所选G研究记录/提交owner | 搜索缓存、Brief摘录 |
| 来源游标/尝试 | 对应采集用例 | 健康展示不可用于恢复 |
| 研究议程 | 所选研究/议程owner | 页面列表 |
| 正式Decision | 后序可信人工确认owner | AI草稿/展示不回写确认 |
| 工程顺序/任务 | #3及各有限任务 | README只链接，不复制状态 |

按[#6当前路线A](https://github.com/auguspp/Decision-OS-2/issues/6#issuecomment-6187561836)，公开仓的 `main` 仅承载工程；独立 `records` 数据分支用于有对外公开权利的来源版本、研究修订和议程。保密材料及凭据不得进入公开数据分支。运行位置以[显式绑定](../../config/store-binding.json)和实际回执为准；未来迁往独立仓库B须保留确切旧引用、只允许一个当前writer。本节路径属于**数据分支**布局，不在 `main` 创建运行数据目录：

```text
research/cases/<case-id>/revisions/<revision-id>/record.json
research/cases/<case-id>/revisions/<revision-id>/research.md
source-views/<content-or-dataset-id>/<version-id>/manifest.json
source-views/<content-or-dataset-id>/<version-id>/<allowed-representation>
```

G首批采用版本化文件表达，不以一个长期大Issue存全部研究；已验评论写入仅作为可用提交通路候选，若采用则明确投递/权威归档关系，不能评论和文件两边都有当前研究。受限对象大于有限导出范围时引用受限读取或声明缺口，不把敏感全文转公开以求方便。

<a id="source-ref"></a>
## 4. ResearchRevision → SourceRef → 真实版本

SourceRef内嵌于研究修订，不强制独立表。最少表达：内容/数据集身份及版本、实际保管表示、实际使用页段/行列范围、取得/披露等用途所需日期、可信接收返回的读取定位及其限制。内部版本与外部URL分开；URL不是永久原件。

G读取形状优先是确切`repository/commit/path`与必要的字节校验，再定位同权限有限表示；内部数据库ID或过期签名URL本身不算稳定的GPT读入口。来源对象换物理位置时仍解析同一版本，不能静默回最新。数据集切片记录证券/指标/期间/选择方法及原版本，不只留下一个文件名。

写入顺序：实际保管获准来源 → 确定可读版本/表示 → 保留关系可识别 → 提交研究修订及明确前驱 → 返回真实位置并读回。前面失败不得给“内部保管成功”引用；后面失败可保留多余待对账对象，不做危险清理以假装全回滚。多个介质不是自动原子事务。

只有外部定位/摘录时仍可保存部分研究，明确无法恢复哪部分；不阻塞不依赖它的结论。已引用或保留关系未同步的对象不按孤儿清理。无权限、缺对象、损坏、暂时不可读分别反馈；拒绝也不得泄露无权对象的正文或敏感存在性。

### 最小研究载荷（合同，不是已上线接口）

`submission_id` 描述同一次意图，重试复用；`case_id/revision_id/kind` 标识案例与修订；`predecessor_ref` 明确前驱；实际研究正文和 SourceRef 集合；委托/方法定位、关键结论与未决/停止说明；可选 `valuation_spec`。不强制概率、股价、统一财务模型或最终结论才能保存。

同键同内容恢复原结果；同键不同内容冲突；新修订与当前指针分开，过期前驱不覆盖新指针。返回的保存时间/commit/摘要来自实际接收，不接受模型自签成功。新版本不继承Human接受。

<a id="permission-levels"></a>
## 5. 实际写入口必须标明强制程度

| 操作 | 可以继承的基础 | 本次新增保护在哪里承担 |
|---|---|---|
| 工程文档/代码写 | GitHub获准分支/PR能力 | 当前分支单写、原生期望值检查、合并前后核对 |
| Quick/Full普通成果保存 | 原研究动作与行为范围 | 已核目标/可见性、公开权利、来源引用、委托/前驱检查；公开数据分支及共享凭据均不得称强隔离 |
| 内容接收/游标推进 | 原件保存/失败与来源资格原语 | 新提交者范围、实际保管后推进、新介质恢复 |
| 研究当前指针/重要修改 | 原版本连续性原则 | 唯一受控写入者+条件更新；无等效控制不启用共享高影响写 |
| 正式Decision/原件删除/权限管理 | 不由普通研究写权限承担 | 相应可信入口/独立凭据或受保护路径，拒绝可绕行的直接写 |

每个启用入口留下实际身份来源、操作对象、强制点、仍属行为规则的限制及测试定位。不是在payload里写`role=human/full`就提权。受保护PR路径只有在同凭据不能直接覆盖目标时才称强制隔离；只靠约定时据实标明。

<a id="calculation"></a>
## 6. Odds的复用边界

继承精度/归一化/每股现金/收益算术和币种/期限拒绝语义；旧ResearchSnapshot提交状态、旧ID/hash和HumanPriceContext输入属于旧适配约束，不强迫新研究伪装。先看真实依赖，再决定直接复用、窄适配或局部提炼。

第一份与价值有关的研究保留实际币种、价值时点、期限、股本/现金口径和来源，不强迫全部Full先形成机器模型。B3开启自动计算前落实新载荷映射：当前公允价值只用于对应估值距离；未来退出价值/分配现金才可按支持方法算条件回报。价格单变不换股本/期限/概率，不将Relay报价改标人工价通过旧入口。

适用旧机械正反例可转成新最小输入回归；不搬旧公司判断、旧reader和永久转换层，不执行模型上传脚本。参照最终设计第14.5章与附录B K类条目。
