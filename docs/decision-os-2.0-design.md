# 01　产品目标、边界与已确定前提

## 1.1 产品要解决的问题

Decision OS 不以“接入了多少来源、保存了多少数据、生成了多少报告”为主要成果。它要帮助用户更早注意到可能改变企业价值的重要变化，提出原先没有想到的问题，形成可检验的经济解释，在价格与时间条件下作出人工选择，并在后来区分认知进步、数据缺口、分析错误和合理但不利的结果。

产品包括观察、发现、理解、人工判断、复盘五项责任。它们可以独立使用、双向反馈，不是五层软件架构，也不是每条信息必须走到底的流水线。没有新机会、经过研究决定不关注、维持原判断，均可能是合格成果。

旧 Kernel 的“小而明确的投资决策核心”可作为本产品内的稳定核心，但不能用它的狭窄定位省略发现、深度研究或 Decision 产品责任。反过来，也不能为了产品完整，把采集、提示词、调度和页面逻辑全部塞进核心。[S01] [S02] [S03]

## 1.2 用户已经明确的前提

## 1.3 目标覆盖不是上线承诺

**首版承诺：在已声明数据覆盖与获准探索范围内主动发现有依据的研究问题。** A 股范围由合格数据明确列出；两个产业贯穿案例不是永久选题白名单。允许范围外有界公开探索，但不承诺全球连续扫描、所有领域机械检测或 500+ 商品同步上线。[USR]

不承诺发现全部机会、普遍领先价格、保证研究真理或收益。人工线索深化、机械扫描和无具体人工提示的自主探索分别验收；一次成功不证明普遍领先，零候选也不自动证明已具有发现能力。

## 1.4 已验证起点与新项目范围

新项目不以旧技术能力全部未知为前提。既有 GitHub 研究读写、跨会话恢复、Full 单委托自主推进、条件计算、Relay 日常输入、完整 CI 和部分真实消费已提供可继承基础。其证据与限定汇总在第 23 章，逐项处置在附录 B。[AUDIT]

继承原范围验收不恢复旧业务状态，也不使新接线自动通过。此后默认问题是“本次改变了什么、需要补什么证据”，而不是“整个能力是否可能”。

# 02　日常工作流与用户体验

## 2.1 用户每天打开系统应获得什么

首页应先回答“新增了什么值得看、哪些旧判断需要复核、下一项最有价值的研究工作是什么”。主要信息用业务语言表达；代码版本、采集批次、哈希和日志下沉至可展开的来源与健康视图。展示预算限制首屏，不裁掉内容池、研究原件或未解决事项。

建议形成四个日常入口：**今日变化、研究工作台、持续跟踪、历史与复盘**。Decision 建设到位后，增加与研究工作台相连的**判断准备与人工记录**入口；不是另建一份事实数据库。

## 2.2 从观察到持续理解

用户随时记录“身边更多人刷短剧”一类观察，附实际观察时间、范围、来源性质与自己的问题。系统保留为人工观察，不升级为总体统计。Quick 在获准范围内关联已有材料、提出渗透与变现问题，找可区分解释的证据；没有公司映射也可继续。

定时 Quick 恢复上一轮问题与本轮真实输入，独立发现、筛选和初查；输出新增、延续、修订和停止理由。用户选择 Full 后，研究者在同一委托内自主推进。重要新证据进入后，优先复核受影响的假设，而不是每天重写整家公司报告。

Brief 消费实际研究和观察，标出来源与研究截止。晨报以相对上次实际晚报的增量为主；晚报综合当次重要市场与研究变化。此分工是目标合同，不在本轮改动既有日程、通知或任务。

## 2.3 Full 与 Decision 的用户旅程

用户可直接说“研究这家公司的竞争力和当前价值”，不要求先制造 Quick。交付时首先回答原委托，再给证据、经济模型、反证、价格要求和未决工作。用户可以继续质疑、认可某版研究、暂缓复核，或明确作出投资选择；这些行为分别记录，不相互推断。

Decision 专门工作流上线后，用户能对照同一时点的 Research、机会表达、行情／Odds、替代行动和重要未知，明确表示继续研究、等待某条件、放弃或作出人工决定。系统保存当时依据与理由，未来复核时不改写过去。没有持仓系统，也能记录“不参与”和“等待”这一类真实决定。

## 2.4 体验中的反例

数据没更新时，不显示“今天没有变化”；未读到 Quick 时，不显示“Quick 未运行”；用户暂缓不变成永久排除；同一股票出现新的反证，不因昨日已经展示而整体去重。没有重要增量时允许短报，不为栏目填满制造研究。[S08] [S16]

## 2.5 减少用户操作是验收的一部分

继续既有问题时，由系统恢复可定位资料和未完成工作，不让用户搬 SHA、重贴报告或再次说明已经批准的研究范围。普通保存、取证和原内部议程接续不逐次索批；只有正式 Decision 增加用户已接受的独立确认。

既有正常入口恢复与自然研究消费已经有原范围证明，新产品只检查新的入口／表达及本次实际使用。用户无需参与重复能力演示；一项旧能力保持工作，应该减少后继工作而不是制造新的验收表演。[EV03] [EV04] [EV09]

# 03　原则、复杂度预算与证据复用

## 3.1 稳定核心负责什么

稳定核心保护对象身份、用途所需的 PIT、来源与版本关系、确定性计算输入、不可静默覆盖的研究记录和人类权限。它校验一致性与使用资格，不给来源颁发永久真理证书。数据、证据、判断、决定和执行是不同事实；UNKNOWN 是合法结果。[S01] [S24]

“证据改变经营判断、价格改变 Odds”是一条防止无解释锚定的纪律，不是声称价格毫无信息。价格带来的新假设应显式交给 Research 复核，不能直接改写经营概率。[S24]

## 3.2 九项统一工程与研究原则

| 原则 | 在目标系统中的具体约束 |
|---|---|
| 成果稳定、方法可换 | 固定可检查的交付与证据责任，不固定私有推理、Agent 数量、阶段顺序或提示词 |
| Reuse First | 先恢复内部实现、原验收和已有选型；仍适用的审阅可以复用。新／实质变化用途再有界检查成熟开源与官方合同，不以“自己写更快”重造 |
| Modularity First | 能力、实现、消费者、组合者分别归属；新增、替换、停用、退役影响合法接点而非无关内部 |
| 先保存、再解释 | 允许合规的有限原始内容入池；入池不等于足以支持任意结论 |
| 按用途资格 | 只要求当前用途真正需要的输入；既不冒用低资格数据，也不叠加无关门槛 |
| 事实可恢复 | 原件、来源、研究修订、人工原话与未知效果保留实际身份；摘要不是原件替代品 |
| 前提变化同步对账 | 需求／方法／权限变化同时处理入口、消费者和验证；不只追加埋在历史中的评论 |
| 生命周期完整 | 新增即明确 owner、消费者和退出条件；专属维护义务随对象退役，共享不变量继续 |
| 比例适当 | 不为每个字段建平台，不为普通修复重审全仓；性能、保护新增与维护减负分别计账 |

原项目已统一原则与路由，并要求保存、登记、发布、验证、接受、执行分别举证。本稿继承这些语义，但不把旧仓 GitHub-only 存储、旧编号、历史例外和全部兼容链当成新产品宪法。[S01] [S02]

## 3.3 四种退出必须分开

运行停用、实现替换、旧执行入口退役、历史读取支持结束，是不同操作。关闭一个实现 Issue 不会结束已上线能力的测试责任；停用采集器不撤销已发生的请求和费用；删除配置不证明未知写入未发生；新方法也不继承旧版 Human 接受。

原件删除、权限提升、公开发布和不可逆支持损失仍须符合实际授权；现有资源使用与不以费用为约束已由用户明确裁决，不再逐项重问常规资源费用。来源文字或规则文件不能扩大权限、替代平台访问批准或改变原任务。[S01] [USR]

## 3.4 首版复杂度预算：不承担的长期义务

此表是范围约束，不是评分、审批系统或表／文件数量配额。增加长期机制时，在相关 Issue／PR 简述真实用途、简单方案为何不足、维护归属与退出；不另设治理平台。

| 能力 | 首版必须 | 首版明确不默认承担 |
|---|---|---|
| PIT | 用途日期、取得时间、研究引用版本，不倒灌未来 | 全库历史截止服务、双时间数据库、任意时点环境重放 |
| Learning | 保存实际成果、交付、明确反馈与纠错；按需 Review | 每轮全链归因、完整漏报率、自动校准／改方法 |
| 历史支持 | 新项目自己的版本按声明保管级别可读、可恢复 | 旧 Kernel／旧 OS 研究格式、状态及执行兼容 |
| 内容与身份 | 原件／数据集保管、查询、必要 ID 与冲突保护 | 万能 JSON、每条主张独立状态机、默认向量库 |
| Research | 完整经济、现金、估值、反证与合理停止 | 固定 Agent 数／研究轮次、强制全来源、全量模型语言 |
| Radar | 少量合格检测＋有界自主探索 | 六类目标各造检测器、全市场无遗漏承诺、通用规则平台 |
| Odds | 有资格的纯计算、条件分析与结构化结果交接 | 补造概率、任意脚本后台执行、自动买卖 |
| CI | **完整四 scope、分层、双级并行、精确复用、身份与退役** | 旧仓专属证据兼容、无用途的历史优化器；不得据“轻量”删减已裁决能力 |
| 工程／运行 | 有限 Issue、责任组 PR、真实读写和恢复、安全隔离 | 多套进度库、逐次全仓审计、第二套长期 Agent 平台 |

费用不是当前取舍障碍；简单、可靠和维护负担仍是设计标准。不因资源充足引入无效复杂度，也不因追求最薄实现削弱 Full 或用户已选择的完整 CI。[USR]

## 3.5 证据复用先于新增验证义务

按“原能力及其证明 → 本次实际变化 → 受影响合同／消费者 → 最小必要补验”安排工作。原回执、自然成果、代码／测试、方法说明四种证据不能互相升级；有相同适用前提的成功验收不归零，局部失败也不把整条能力归零。[EV01] [AUDIT]

正常新仓读写、正式 PR、一次真实研究或真正的后继变更能够提供证据时，不另建同形 pilot。重复验证被取消，不表示新代码可以跳过适用完整 CI，或新鉴权／存储免于必要反例。

原开源／组件审阅在用途、版本与约束仍适用时直接沿用；实质变化才补查对应差异。证据失效需要原因，不能只因为“新会话”“新版本文档”“从零重建”就重新审计全仓。没有找到材料先记定位缺口，不自动写一个替代实现。

# 04　全量能力地图与责任关系

## 4.1 完整能力，而非十二个独立平台

| 能力 | 主要输入与输出 | 权威责任与建设顺序 |
|---|---|---|
| 采集与接收 | 来源响应／人工材料 → 原始版本与采集回执 | 后台；早期必备 |
| 内容与数值底座 | 原件／数据集 → 统一目录、检索、质量与覆盖 | 后台；早期必备 |
| Radar | 合格观察 → 变化、异常、基线及检测处置 | 确定性方法；早期最小版 |
| 产业关系与暴露 | 产品／产业／公司证据 → 有来源的关系与传导假设 | 关系合同＋研究者；早期最小版 |
| Quick | 观察、旧问题、独立查证 → 新问题、初步解释、Full 建议 | 获准 AI 宿主的定时任务；研究是核心能力，宿主可替换 |
| Full Research | 明确委托＋资料 → 经济与价值研究、反证、修订、复核条件 | 受委托研究者；早期核心 |
| 估值与 Odds | 指定研究／情景、行情、期限、政策 → 类型明确的条件结果 | 纯计算＋方法政策；按需接入，不阻断研究 |
| Opportunity | 变化／研究／市场条件 → 为什么现在看、期限、条件与失效 | 研究产物投影；早期轻量、后续完整 |
| Attention | 候选、反证、到期事项、用户反馈 → 可解释阅读队列 | 单一注意力政策；早期最小版 |
| Watch | 指定版本的条件 → 已检查、触发、未满足或无法判断 | 跟踪用例；早期研究跟踪、后续决定条件 |
| Brief／晨报 | 已有观察与研究 → 面向人的增量交付与使用回执 | 交付消费者；早期必备 |
| Decision | 判断准备＋人工明确表达 → 同时点决定记录与复核约定 | Human；完整设计、较晚实现 |
| Learning | 实际成果、明确反馈和后续事实 → 按需复盘；可选专项评价 | 首版复用已有记录，不作为通用执行框架 |
| Workbench／聊天工具 | 同版本读模型与受限命令 → 日常使用与安全写回 | 接口层；聊天优先，页面逐步建设 |
| 运行与工程 | 调度、持久化、权限、CI → 可靠交付与恢复证据 | 运行／工程 owner；始终贯穿 |

## 4.2 三条相互补充的入口

**系统观察入口：** 采集 → 内容池／类型化数据集 → Radar → Quick → 可选 Full。

**研究者入口：** Quick 或直接 Full 独立查证 → 新内容与假设 → Research，不必先经过 Radar。

**用户入口：** 人工观察、上传资料、直接委托或挑战 → 研究案例。用户不是专职数据搬运员；来源可由获准研究者取得时，不把材料搜集默认交回用户。

Full 的关键变量反向进入研究议程，后继观察可唤起针对性复核。Decision 和 Learning 消费明确版本，不改变其上游原件。任何链路都允许有依据的“无需继续”，不强迫最终产生交易。

## 4.3 各能力的继承类别

Quick／Full 执行及接续、确定性 Odds 和完整 CI 以已有实现与原验收起步；统一内容接收、`valuation_spec`、新行业关系与研究展示主要是组合和接线；新全文索引、新数据库恢复、服务端角色隔离、独立 Decision 确认是相应目标采用时的新增责任。各类不能按一个“尚未验证”总状态管理。[AUDIT]

逻辑上共有内容目录，不要求物理上所有研究与批量数据同步迁入一个新库。研究工具入口沿既有 GitHub 路线起步，内容存储与大原件承载独立选型，见第 20 章。

# 05　信息对象、身份与版本合同

## 5.1 对象归属：统一目录，不统一成巨型 JSON

| 逻辑对象 | 首版表达与归属 | 按用途扩展 |
|---|---|---|
| ContentVersion／Dataset | 来源、类型、日期、取得时间、内容引用；文本与数值分类型保管 | 扩大规模、附加解析或搜索索引 |
| Entity／Relation | 必要主体身份、别名和有依据的关系；真实用途内维护 | 跨案例关系或共享前提索引 |
| ResearchCase／Revision | 问题、范围、正文、来源、假设、计算、挑战、前驱与剩余工作聚合保存 | 需要独立追踪的假设再单列 |
| EvidenceUse／Hypothesis | 普通引用、主张和假设内嵌于研究修订，不逐句拆数据库行 | 有独立查询或 Watch 消费者时提取索引 |
| Model／valuation_spec | 底稿可读；仅接后台计算的结果附受限结构化产出 | 新模型映射经验证后加入，不开放任意代码 |
| Opportunity／Watch | 机会可为研究视图；研究议程只登记重要条件 | 价格／通知／决定跟踪按实际授权启用 |
| Delivery／Feedback | 单次 Brief／队列记录选取、必要省略与实际反馈 | 不为所有未展示输入创建独立处置行 |
| Decision／Review | Decision 草稿与受信确认区分；Review 为简短引用式复盘 | 专门界面与分析后序建设 |
| Run／Checkpoint／Health | 本用例实际需要的执行、效果与恢复字段 | 无真实用途不拆成独立平台 |

这些是责任划分，不是建表配额、六层调用链或全套远端接口清单。每项事实只有一个权威写入归属，派生索引可重建。首批实施仅物化真正有 writer 和 reader 的记录；不能为了对齐图表先搭空壳。[REV1] [REV2]

## 5.2 身份与命名

实体 ID 不含数据商、中文显示名或当前行业分类。公司与证券分开；同一公司不同股类、上市地、币种分别标识。证券代码重用、退市、改名、并购不自动合并历史。商品身份至少可表达产品、规格／品级、地区、币种、单位和报价／成交／期货口径。

对象 ID、内容哈希、版本引用各有用途，但不要求每份记录都同时生成一组 UUID、版本号和多层摘要。Git 原件可用确切 commit／path／必要字节校验作定位；评论用真实 ID 及已保存内容界限；新数据库记录按实际去重和引用需要设技术 ID。来源业务键用于识别重复，不能单独代替内容版本。

已引用版本应稳定可读；可编辑评论若被用作保存入口，必须明确不可变保管在何处完成，不能以评论编号宣称平台强制不可变。哈希只证明相应字节，不证明真理、授权或当时已知。格式在具体接线中确定，不复用全部旧 hash／schema 义务。

软件版本、数据 schema、解析器版本、算法／政策版本、研究修订和人工确认各自独立。显示名可变不重写原件；原始文件名与字节保留，不为目录整齐批改历史。[S01] [S03]

## 5.3 记录不是一条总状态

研究已保存、研究范围充分、行情可用、概率合格、用户已回应、Watch 已启用、通知已发送分别记录。不要让一个 `READY` 或 `DONE` 同时代表六件事。核心状态只在确有机械用途时结构化，其他用简短的限定说明承载；不预先把所有研究概念做成枚举。

## 5.4 两种研究入口共用对象，不共用覆盖权

Quick 可以新建选题或在已有案例追加观察，Full 可以从直接委托建立案例或引用 Quick 进入深入研究。两者引用同一权威来源与修订关系，持有各自允许的写入范围；Quick 新反证不覆盖 Full 正文，Full 修订保留其前驱及重要争议。

普通证据使用、假设和剩余工作随一份研究聚合保存；有独立检索或条件跟踪用途才建立索引。部分研究保存与当前修订选择分开；不能要求先完成最终估值、PIT 全库快照、Learning 分类或 Decision，才允许留存成果。已有进度／归档原语可复用，新增提交键、并发或指针只验其差异。[EV11] [EV12]

<a id="chapter-06"></a>
# 06　统一内容池与采集生命周期

## 6.1 采集器只负责取得，但不得省略来源语义

采集器负责获准端点／网页／文件获取、参数、分页、限速与原始回执；可输出来源固有元数据，不决定公司受益、研究优先级、Watch 或买卖。解析与标准化可以与适配器同进程，但合同上可单独重跑，不需要再次请求来源。

统一的是接收、保管、目录与检索合同，而不是将 RSS、财报、行情和人工观察的恢复方式强行统一。批量市场数据按数据集保存，不伪装成几百万篇新闻；文本、表格、PDF 和人工笔记保留各自保管等级。

## 6.2 建议的成功边界

取得响应 → 可靠保管获准内容／原始回执 → 登记可引用版本 → 在实际持久完成后推进来源进度。沿用既有保管与失败原语，不因为重建就重新验证同一字节写入机制。

采用“数据库＋对象目录”时，先写不可变对象再提交引用；这不是天然跨介质原子事务，中断后的无引用对象可有界对账，不能产生指向不存在原件的成功记录。沿用 Git／有限文件保存时使用该通路的真实提交与读回，不为同一效果额外增加一个事务平台。换介质造成的新边界才补验。

解析失败仍保留原始内容与错误；保存失败立即阻止相依游标推进与后继请求。保管异常不能被宽泛“来源异常”吞掉。请求已经发生，其预算不因本地回滚而退款。该规则继承旧 #868 的已记录合成故障教训，而不是假称原生产曾发生磁盘事故。[S11]

## 6.3 重复、修订与重试

同来源同版本重复取得，复用内容对象但保留取得记录；同 URL 正文变化，新建版本；转载可聚类展示，但原上游关系保留，不把十个转载当十个独立证据。语义相似不自动合并不同事件。

内部处理允许幂等重试；外部调用按来源合同与剩余预算决定。无法确认远端是否写入时先对账，不用新日期、新路径或新任务身份绕过去重。稳定幂等键描述同一次意图，不能由每次重试重新生成。检查“尚不存在”与实际创建之间仍需唯一约束／条件写，避免并发竞态。

## 6.4 再处理、保留与停用

解析器更新可以基于同一原件产生新派生版本。旧解析结果仍可被历史研究引用；新版本不倒灌过去。停用采集器不删除已入池内容，不取消其仍有效的保管责任；退役时同步退出专属定时器、权限、测试和配置。

保留策略按用途与权利区分：被研究／决定引用的合法证据随引用保留；普通未引用内容可以限期保存；不能留全文的来源只保存获准摘录或元数据，并标明恢复限制。到期清理先查引用，不能只凭创建时间删掉核心依据。

## 6.5 Research Source Intake：研究取得的资料使用同一保管合同

Quick／Full 在研究中取得的网页、PDF、表格、摘录，和采集器／人工上传共用接收、版本保管与引用返回路径；不另建研究资料库。研究者可提交获准留存的实际内容，或请求已有获准获取器取回明确来源。

接收至少说明来源定位与角色、资料日期／期间及已知披露时间、取得时间及其证据性质、保管形式（原字节／提取文本／摘录／元数据）、内容或真实文件引用。服务端独立记录接收时间、实际保存对象与字节摘要值，返回可读的内容版本。模型自述取得时间不冒充服务器实测；摘要值只对实际取得并保存的字节计算。

同意图重复提交恢复既有结果；同键不同内容冲突；同 URL 新正文产生新版本。来源内容、来源中的指令及模型生成脚本均不得触发执行或增加权限。远端取回需限制地址、重定向、大小和解压路径。

研究只引用真实返回的版本；原件不可保留时允许合法摘录或定位，并明确恢复限制。保管不完整不禁止保存部分研究；结论资格仅按其真正依赖的证据裁定。不能为了统一入池，要求所有 Full 先保存每一份完整 PDF。[REV1] [S20]

## 6.6 保管与恢复的已有证据

旧进度保存、研究档案和三类 Odds 留存已有原字节、前驱、独占写和重建实现；RSS 的真实云端前驱恢复与无变化续作也已验。#868 的合成写盘失败、#865 的实际归档空目录问题提供必要反例。[EV11] [EV12] [EV13] [EV20] [EV21] [EV22]

统一 `intake_source` 应复用这些语义和合适原语，而不是整包搬旧 reader。新增回执、资料权限、引用方式、并发或存储才是差异；不重抓 RSS 同一窗口、不重造磁盘事故，不把旧格式兼容带回新项目。

## 6.7 GitHub 研究引用到内容池的最小接线合同

**目标关系：`ResearchRevision → SourceRef → ContentVersion / DatasetVersion`。** 这是研究中的有限引用结构，不要求单独的 SourceRef 服务、引用表或全库快照。G 路线下研究版本由所选 Git 记录承担权威，内容版本由其保管用例承担权威；数据库中的研究搜索索引只能派生，不能竞争写入同一“当前研究”。公开项目仓不自动获准保存私人研究。

| 引用需要表达的事实 | 最小责任 |
|---|---|
| 来源与版本 | 明确内容／数据集的稳定版本和保管形式；原字节、提取文本、摘录、仅外部定位分开 |
| 实际使用范围 | 文档的页／段落或数据集的证券、指标、期间、选段；没有原页不得补造页码 |
| 实际读取入口 | 采用已获准的 Git 固定文件／有限导出或已经支持的受限读取操作；内部数据库 ID 本身不算研究宿主可读入口 |
| 保留与权利 | 被接受为内部证据引用的对象进入相应保留范围；不能保存全文时只引用实际获准保管的表示 |
| 解析结果 | 读到确切版本，或明确权限拒绝、对象缺失、损坏／身份不符、暂时读取失败；不得静默换最新版本 |

B0 只固定首批研究权威、引用形状和实际解析路线；B1 的首次正常研究保存／读取验证新接点，不再重做 GPT 读写 GitHub 的通用试验。源对象先实际保存并取得可读引用，研究再引用它；内部保留关系须在研究引用被接受时可识别。跨 Git／数据目录不假称原子事务：失败可以留下有界待对账的多余对象，不能留下被宣称成功却指向未保存对象的内部引用。若研究暂只保存了外部定位或未完成来源保管，明确该限制，不阻止保存部分研究。

自动清理启用前必须覆盖 G 路线引用的发现与保留；引用索引未同步、读取不完整或保管责任不明时，不将对象当作无人引用删除。恢复后核实际解析结果；后续权限收紧可使内容不可读，但不得用另一来源或新版本冒充原依据。研究版本与内容身份保持来源可解释，不承诺永远可访问或 100% 原件恢复。

<a id="chapter-07"></a>
# 07　来源适配、市场数据与覆盖资格

## 7.1 一个行情入口，不是所有信息一个来源

市场用途由来源适配器提供合格输入，供应商名称不成为核心判断正确性的定义。A 股日线当前沿 [FTShare 日线合同](sources/ftshare-daily.md)运行；其他现役 Relay 用途及旧来源历史沿各自合同保留，不在本次路线调整中切主源或建设多行情提供方瀑布 fallback。有界请求、来源回执、凭据保护和有限重试继续生效；能识别的真实上游须注明，两个转售商读数一致不自动证明上游独立。[S19]

用户已同意少量成熟、用途明确、维护可控的常驻内容源，不采用“首版零新增内容采集器”的绝对限制。优先复用原有可靠 RSS、公告或成熟适配，说明覆盖缺口、权利、运行责任与退出方式；不为凑目标增加脆弱抓取器。[USR]

人工观察、文件上传与 Full／Quick 的有界公开查证独立接入。一次查证不自动形成永久采集器；Relay 摘要不自动满足原文核验。常驻源的接线和日程按后续实施范围启用，不因本稿修订立即修改旧任务。

来源使用分为三种用途：研究期取证默认临时；进入判断的证据先固定必要且有保管权的表示；机械 Radar 保留扫描分母、时点、缺失和规则版本。沿现有 `SourceInput` 的 provided／excerpt／external 区分实际收到的表示、摘录与外部定位；缺上游 HTTP 原字节不一概禁止部分研究，但不能把包装 JSON 的摘要当上游原件认证。需要原始响应、完整路径或复权依据的特定用途仍须满足自己的资格。尚未完成适配、权利及用途验收的连接器保持研究期取证，不自动进入公开 records 或生产采集。

## 7.2 数据用途清单

每个首批实际采用用途说明必需字段、主体／单位／日期口径、范围、授权、运行限制及维护归属。优先引用已有样本和用途验收；端点、参数、口径与执行环境未实质变化时，不重复请求同样数据证明可用。

`trade_cal`、`daily`、`adj_factor` 及日常 5／20／60 端点比较已有真实取得、重建、发布与消费证据，是可继承输入，不是 B0 假设。其他财务、期现货、运价等用途逐项查既有证据，缺证且实际需要才有限补验；不能凭接口目录或一个 daily 成功宣布全部可用。[EV18] [EV19] [EV05]

先支持证券身份、交易日历、日行情、公司行动／复权必需资料和关键财务披露；跨市场、期货、机构行为和更多产业数据按用途扩展。完整目标设计容纳这些能力，不以第一批接口规模决定未来产品边界。

## 7.3 市场数据最小合同

| 检查维度 | 需要表达的内容 |
|---|---|
| 证券与公司 | 交易所、股类、币种、稳定 ID、上市／退市／停复牌及公司行动 |
| 价格 | 原始还是调整价、价格类型、交易时段、市场日与实际报价时刻 |
| 复权与收益 | 因子来源和版本、所用公司行动；区间价格比不自动称含分红总回报 |
| 日历与缺口 | 已完成交易时段、应有观测、停牌、未上市、缺失、未请求分别处置 |
| 期间和比较 | 共同终点、窗口定义、同证券同口径；5／20／60 是不同资格 |
| 期货与现货 | 合约、到期与换月规则、连续序列构造；现货地区规格与报价性质独立 |
| 财务与预测 | 报告期、披露／修订时间、会计口径、币种单位、归母／合并、股本与预测角色 |

合格端点可支持端点区间比较，不必被不相关的中间缺日阻断；完整逐日路径、事件前后反应或波动计算需要其真正所需观测。未知复权因子不填 1，缺失价格不填 0，最新失败不以任意旧成功替代。[S16]

## 7.4 覆盖分母

计划范围、实际取得、用途合格、实际分析和最终展示必须可以区分，但不每天重复保存七套完整名单。建议复用一个范围版本，记录本批必要计数和异常／剔除集合；数据库已有完整处置时以查询引用为主，必要时保留有限快照。差分链不能无限增长到无法恢复。

声明全范围机械扫描时，范围成员须有处置；语义 Quick 只声明实际阅读／检索范围，不为尚未形成的想法建立记录。未配置不是来源故障，未读不是无价值，未展示不是用户拒绝。缺完整分母时不报告完整覆盖率或漏报率。

当前名单回看不称历史当时可投资宇宙。首版 A 股主体范围在数据资格验证后明确列出，两个产业用例不限制其他获准选题。500+ 商品的规格／用途清册可以分期发展，未支持领域明确暂未覆盖，不填零或补造价格。[USR] [REV1] [REV2]

## 7.5 不重复建设现役来源能力

继承同一来源的有界请求、响应保管、临时失败分类、逐期限资格和最新失败／最后合格分开呈现。新来源适配到 Odds、Watch 或新表结构时验证来源与用途映射；不能因字段同名或数字相等就当成原用途完全等价，也不恢复多行情 fallback。替代活动采集责任前须先有真实消费者和回退，历史 SourceRef 不能失读。

旧 RSS 的无时区发布时间问题只限制依赖精确发布时间的用途，不阻止以实际取得时间保存有限内容。原证据未覆盖自然新版本到达时先查后继记录；不为普通入池强迫解决旧 Evidence 导出链全部问题。[EV19] [EV22]

<a id="chapter-08"></a>
# 08　按用途 PIT、质量、检索与证据使用

## 8.1 两种历史问题必须分开

**首版 PIT 是按用途触发的正确性约束，不是通用历史时间数据库。** 普通内容保留来源日期和实际取得时间；财报区分报告期、披露／修订时间和取得时间；行情保留市场日／报价时刻与取回时间；研究保留实际使用的来源版本及其声明范围。没有的时间可为 unknown，只有日期不编造秒级首发时间。

“公众当时可能知道什么”和“本系统当时实际取得什么”仍是不同问题，但首版不因此提供两套全库查询。今天补到旧资料不能证明过去已经收到；当前修订值不能伪装成当时预测输入。新版本保留前驱，不静默改掉已引用的材料。[S01] [S16]

| 等级 | 范围与保证 |
|---|---|
| 首版必需 | 上述用途时间、披露与取得区别、研究输入版本与更正；新记录可读 |
| 后续按需 | 某个实际用例的历史截止读取、数据修订对照或回测；单独声明时钟、版本和缺失 |
| 非默认义务 | 任意时点全库重建、全对象双时间索引、旧环境重放；旧 Kernel／旧 OS 研究兼容明确不承担 |

本版不要求普通查询提供 `knowledge_basis` 或全局历史快照。严格历史问题没有实现时如实说明不支持，不能用当前值补算并冒充当时所知。[USR]

## 8.2 质量不等于全局分数

质量应拆为身份、完整性、时效、单位口径、保管等级、解析状态与用途资格。一个来源中的已报告收入、管理层目标、估算和评论，其支持能力不同；不能给整份报告一个可信分数后放行所有结论。[S24]

证据使用绑定具体原件版本与位置，说明它支持、反对或限制哪项主张。只有标题可以用于初筛，不能冒称全文核验；原文、合法摘录、提取值、模型转述分别标识。同一资料在不同 Research 中的使用方式可以不同，不能因上次被采用就永久成为“工作真理”。

## 8.3 可解释检索

首版提供实际需要的主体、来源、类型、日期／期间、关键词和研究引用过滤；明确分页是否完整、查询是否受限，未知总数不伪造。证券代码、产品编号、明确别名优先走精确索引；正文检索是另一用途。

SQLite FTS5 可作为候选。官方说明 trigram 全文查询中的不足三个 Unicode 字符的子串不能匹配记录；默认 Unicode 分词按字符类别划分，不提供中文词汇切分。LIKE／GLOB 的执行路径与全文查询不同，不能把“全部中文完全无效”或“一定走索引”写成定论。[O08]

方案比较可包括成熟中文分词预处理／扩展、实体别名字典和有界短词检索。不得只靠未经验证的默认 tokenizer，也不在目标稿提前锁定某个分词库。用“短剧”、双字简称、证券代码、同名公司、商品规格、混合中英文和零结果样例验收实际召回与延迟。小范围扫描未必不可用，须有明确范围与实测。

向量检索不是首版必要条件，也不替代确切 ID、日期、来源和数值查询。查询失败、超时或未完成分页不能被呈现为不存在。

## 8.4 读取快照与失败

普通查询返回本次实际取得的记录与版本；后续正文读取按该版本进行。研究保存自己实际采用的输入清单，不强制冻结整个内容池。需要稳定分页或数值整批比较时，使用有限查询快照／数据集版本／明确高水位，不升级为任意历史时点服务。

新 Web 证据保留自己的来源与时钟，不伪装为旧输入。来源更新、解析更新和研究更新分别记录必要差异；不为了这些区别建立三套状态服务。

检索无结果、索引未完成、权限不足、分页未完与原件缺失如实区分。可选补充失败不吞掉主材料；关键证据损坏只限制依赖用途。当前无来源不以任意旧成功冒充最新。

## 8.5 验证继承边界

原身份／日期／来源角色及冻结研究的反例可提炼复用；轻量化只缩减首版支持范围，不允许未知时间补成精确时刻。新字段与读取用途变化按对应样例验证，不建设全库回放作为前置。

既有研究入口发现、目录搜索与分页已经有相关证据；新全文检索不因此自动通过。中文短词、代码、同名实体和规格是新索引的真实查询样例，使用新工作集验证即可，不重建已验浏览器／分页平台。[EV04] [EV29] [AUDIT]

<a id="chapter-09"></a>
# 09　Radar 与主动发现

## 9.1 按变化问题组织，而不是按网站组织

目标可发现六类变化：消费／技术渗透、产业需求与供给、价格／库存／运价、经营与资本行为、市场价格／成交结构、已有研究的重要假设变化。六类是产品视野，不等于六类都需要机械检测器。

| 发现通道 | 首版输入与方法 | 不能替代的能力 |
|---|---|---|
| 覆盖内机械检测 | 经现役适配核验的合格数值／结构化事件，及用途合格的产业序列；明确基线和范围 | 排名不证明经济受益，也不证明所有行业已观察 |
| 无具体提示的 Quick 探索 | 少量获准常驻内容、已有材料与有界公开查证；自主提出问题 | 不凭常识补造新事实，不把用户预先给出的线索算自主发现 |
| 人工线索深化 | 用户观察、上传或直接问题；形成假设与经济关系 | 能分析短剧观察不等于系统已自行发现短剧趋势 |
| 已有研究复核 | 明确重要前提、未来事件和已取得新证据 | 同实体新闻不使所有关联研究自动失效 |

有结构化输入才设机械基线；非标供需、消费或技术问题可由语义探索承担。常驻内容源按用户已选政策开放，不因 Relay 没有某个序列就编写野生抓取器，也不将该领域永久限定为只能人工输入。[USR] [REV1] [REV2]

## 9.2 一个检测器的合同

检测器声明输入数据用途、扫描宇宙、基线、窗口、参数版本、输出条件和失败边界。异常可以来自相对历史基线的偏离、持续变化、跨指标分歧、首次出现的新事实或已有条件被触发。基线方法按数据性质选择，不统一用一个阈值衡量股价、商品报价和使用渗透。

输出至少说明变化对象、方向／幅度或事实差异、比较时点、覆盖、数据质量、触发理由、依据和未决问题。异动排名不是因果排名；“为什么值得看”与“为什么发生”是两层回答。

## 9.3 多维组合与领先性

需求、价格、库存、产能、经营结果可以组合成一个待验证解释，但先核对象、期间、单位和独立性。多个转载、同一统计口径衍生的指标不重复计票。价涨量增也不自动证明需求拉动，可能有补库存、供给扰动或口径变化。

领先指标必须先声明预期传导和可观察结果，后续用原时间线评估。不能见到未来股价上涨后，再把过去任意数据命名为领先指标。短期强势、行业扩散和基本面拐点分别表述，不把一种结论升级成另一种。

## 9.4 参与者、全球背景与事件日历

目标观察包括机构调研、研报修订、股东变化、回购和其他已获准的资本行为，但只把它们作为行为证据、预期线索或查证入口。供应商的游资别名不认证自然人身份；季度持股不是实时仓位；成交额不是净买入；回购计划、累计实施、本次差额与实际注销分别看待。参与者观点不为公司经营真相背书。

全球市场、汇率、利率、期货和产业事件按各自币种、时段、市场日和用途解释。海外财报可以启发本地产业研究，但没有产品／客户／成本关系证据时，不直接复制利润弹性。日历同时保存计划、确认与实际发生，关键研究验证窗不能只依赖新闻恰好命中；窗口到了却未取得资料，应留下具体读取／查证缺口。

## 9.5 候选、零候选与探索空间

第一阶段只需要让高价值问题可见，不要求全部候选都有股票、有估值或有 Full 建议。排序保存理由；保留负面、无公司映射和未上涨对象。对已知关注之外保留有限探索空间，避免只在熟悉名单中循环。

实际完成扫描且无触发可以是零候选；输入不足、未执行或未读完不能称零机会。规则参数或对象宇宙变化时，结果带新版本，不把两个不同规则的成功样本拼成同一稳定性能。

## 9.6 发现验收先查既有成果

日常市场输入去固定名单和行业前置已有实现及实际读取；Quick 自主调查和行业观察也有自然成果。检测器只对新规则／新数据表示补正反例，不为“独立发现”另建第二采集链。[EV05] [EV18] [EV19]

“无具体提示的陌生问题发现”按场景 G 的输入条件查已有自然成果；满足条件即可作为原范围证据。不足时纳入下一次正常 Quick 观察，而不是强制选事后赢家重跑。生活观察 B 只证明用户线索深化，不代签 G，具体新入口尚无证据时如实保留。

<a id="chapter-10"></a>
# 10　产业关系与公司经济暴露

## 10.1 三层表达

**实体关系**回答谁与谁有联系，例如公司生产产品、采购原料、服务某客户群。**传导假设**回答为什么变化可能影响经营，例如涨价传导、销量扩张或成本被客户吸收。**暴露判断**回答影响的量级、持续性、约束、反向因素和集团重要性。

关系记录带证据版本、适用期间、来源角色和实际核验状态；AI 可以提出待核关系，但不能将概念标签直接保存为经营事实。公司集团、子公司、权益比例、报告分部和分析引擎需要区分。[S17]

## 10.2 经济暴露的最小问题组

| 通道 | 需要回答的问题 |
|---|---|
| 收入 | 哪个产品／客户／地区受影响？量、价、份额、take rate 如何进入收入？ |
| 利润 | 原材料、人工、能源、折旧、合同与竞争怎样抵消或放大变化？ |
| 现金 | 回款、库存、预付款、营运资金和资本支出怎样改变现金？ |
| 资本与归属 | 谁投资、谁融资、谁承担损失？少数股东和稀释后归谁？ |
| 时间 | 报价到订单、交付、确认收入和回款各有多久？当前报告对应哪个阶段？ |
| 证伪 | 哪些观察会推翻“受益／受损”的解释？还可能有哪些替代机制？ |

暴露数值缺失时保留未知，不以行业成员、关键词频次或模型信心补造百分比。展示该关系时明确“暴露量级未核”，不把它排成已量化受益证据；仍可因调查价值优先展示。关系更新不自动改写历史研究，只按明确依赖提出相关待复核项。

## 10.3 两个贯穿案例

短剧观察应推进到：观察样本范围、渗透与付费、内容／发行／流量／工具的利益分配、相关企业实际业务、竞争与获客成本、利润能否留给股东。即使不能确定上市公司，也可以形成有意义的行业研究问题。

商品涨价应推进到：规格、地区、报价与成交、公司产销量和业务占比、合同售价、成本、库存、持续性及传导时滞。价格上涨不是集团利润提升的直接证据。两个案例均为目标验收设计，不是本稿对具体产业或证券的投资结论。

## 10.4 复用有限关系能力，不宣称全行业已会推理

旧 `economic_company_context` 已把产业输入与明确公司 Evidence 字段组合，保留来源角色、传导假设、现金／资本和未知量级。这提供轻量关系设计与反例基础，不需要重新研究旧圆通／牧原案例证明“关系表可行”。[EV23]

新项目补的是新关系表示、新内容接入和真正使用中的经济查证。原有限映射不证明任意产业自动识别受益公司，AI 给出的新关系仍须有可核依据；不以图数据库、更多边或关键词命中替代研究。

<a id="chapter-11"></a>
# 11　研究案例、假设与争议管理

## 11.1 研究案例是工作主线，不是新总状态库

一个案例组织一个有限问题，可涉及多个实体、多个假设和多个 Research 修订。它引用内容、证据、模型与决定，不复制它们的权威事实。并行子问题可以保留各自进度，不能用“整个案例已完成”遮住关键未完成分析。

案例可由 Quick、人工观察或直接 Full 建立。保留起始问题、当前问题、范围变化原因及实际委托关系。新证据可以重构问题；悄悄缩小原委托以取得完成标签不被允许。[S20]

## 11.2 假设合同

假设至少表达命题、经济机制、适用对象／期间、支持与挑战、关键参数、替代解释、判别证据、当前可做工作、未来复核条件和版本。假设不是永远正确的结论；观察支持一个环节，不等于证明整条传导。

可采用候选、调查中、限定支持、受挑战、退出／被替代等描述，但数据是否可用、研究是否充分、用户是否接受是独立维度。证伪条件观测到后，旧判断不能继续无提示地用于相关决策；是否真正证伪由复核解释，不直接生成买卖动作。[S24]

## 11.3 主张与不确定性

事实记录、计算、推断、假设、预测、管理层声明和市场背景分别标识。输入在某版模型中可作固定基准、可变参数或仅背景；点、范围、情景联动是表示形式；测量、估计、模型结构和未来状态是不确定性的来源。三者不混成升级阶梯。[S24]

相互冲突的证据可以并存，说明冲突在主体、口径、时点还是解释。新结论须给来源或方法理由，不以“更多来源”投票。已保存旧材料上的补算、纠错与重新解释是合法研究增量，无须虚构新外部事件。

## 11.4 并行研究与冲突处理

两个研究者可以对同一案例分别提交候选修订，必须绑定各自起点。默认不覆盖案例当前指针；提升为当前可用修订需条件写及明确范围。无法合并的解释并列为争议，不自动择最新文本为真。

用户原话、作者自评、独立审阅和工具验证分别归属。没有新的人工表达，不继承旧版接受；同一模型换角色不冒充独立审阅。

## 11.5 共享前提与陈旧度：只对真实依赖联动

普通假设内嵌于研究修订。确有跨案例复用的关键前提，可用前提 ID 或“引用哪一研究的哪条命题”表达依赖；不要求所有实体关系都升格为共享假设库。

新证据挑战同一命题及其适用期间时，列出明确依赖它的活跃研究供复核。仅同公司／同产品相关不触发全图失效，不自动改变结论、概率或 Decision。尚未核验的新闻只能产生查证线索。

显示最近实际复核时间与适用事件窗；已知财报已披露却尚未读回时提示“新披露待复核”，只有计划日期则提示待核事件，不声称结果已经发生。陈旧度是当前使用限制，不是自动证伪或新的投资判断。[REV2]

## 11.6 研究接续的继承与新增范围

部分底稿、显式前驱、独立恢复及实际研究议程已有先例；沿用其问题、当前工作与许可分离的语义。无需再造一个通用 checkpoint 服务。[EV04] [EV11] [EV24]

跨案例前提联动、并发候选选择、新陈旧度提示只有实际接入时才补验。日期到期不等于证据出现，状态标签不等于判断错误，也不自动授权 Full。

<a id="chapter-12"></a>
# 12　Quick：继承已验证的定时主动研究

## 12.1 定位与权限

Quick 是有边界的主动发现与初步研究，不是摘要器，也不是缩短版 Full。它可在授权范围内自主选题、关联公司／产业、公开查证和修订问题。Radar 是视野补充，不是唯一输入或价格门槛。允许零候选、部分成果和当前原因未知。[S01] [S20]

周期性 Quick 由获准 AI 宿主执行，优先复用成熟工作台的研究能力，不另建模型 API worker、通用 Agent 编排或自动 Full。现役 GPT 任务在新宿主真实读、获准写、独立读回和定时运行分别通过前继续承担原责任；切换须对账在途意图、最后输出和回退，不能双主生产。既有 Hosted Quick 的 GitHub 读取、研究保存和后继成果按原范围继承，不跨宿主代签。[EV02] [EV05] [EV06]

新仓目标、资料入口、任务配置与载荷变化在首次正常使用核对；只有新的定时专属 API、鉴权或中转才需针对它验证。原日程／权限本次不修改，旧成功也不扩成任意新操作许可。

## 12.2 每轮应恢复与产出什么

输入先恢复可定位的上次成果、未解决高价值问题、实际覆盖摘要、声明范围内紧凑观察和研究议程，再按价值下钻。提供方总条数不是本轮已读条数。完整宇宙太大时记录抽样／分页与未读范围，不自报全市场扫描。

产出说明：发现了什么、为什么值得看、已有证据支持到哪里、关键计算、最强替代解释、未决项属于哪种性质、是否建议 Full、停止／重开条件、与前驱的增量及实际保存状态。Full 建议不是自动启动许可。

## 12.3 消费增量而非重复生产

分别比较来源增量、研究增量和交付增量。来源未更新不等于已经分析；旧材料第一次分析不包装成今日新事件；同公司新反证不因公司去重而丢失。尚可解决的旧问题不能因滚动窗口到期永久消失。

周期任务使用稳定执行意图身份防重复；每日默认一次也不能禁止合法更正和显式后继研究。重复任务恢复已有结果；修订引用前驱，不通过换标题制造第二份同日研究。保存失败不重做研究，未知写先对账。[S08]

## 12.4 Quick 的质量验收

验收真实新问题、产业到公司解释、反证使用、范围诚实、与旧研究的接续和后继交付。候选数、字节数、来源条数和后来股价上涨不是单独成功标准。出现实际缺陷时可按覆盖、语义、工具和交付区分，不要求每轮执行完整归因；未执行或读取失败不能得到“无有意义增量”结论。

## 12.5 成果保存属于研究委托，不让用户再次催促

在已有授权和可用写入路径内，实质研究成果应由 Quick 自己保存并据真实定位读回；不能只输出报告，再让用户要求“帮我写入”。源未变但尚有已获准分析未完成时可继续；同意图已有成果时先恢复，不重复生成。

迁入新仓时，首份有价值的正常 Quick 保存可以同时验证新目标和资料接线。无需新增一个仅证明“GPT 能写 GitHub”的任务，不把旧日志本身迁成新系统无限运行账本。[EV03] [EV06] [EV10]

<a id="chapter-13"></a>
# 13　Full Research：完整自主研究委托

## 13.1 Full 是首版核心，而不是更长报告

用户直接委托和选择 Quick 后委托共用一套成果合同。Full 可以推翻 Quick、改变问题结构，不制造并未执行的 Pre／Quick。它不以持仓或 Decision 上线为前提，也不要求内容池先取得全部资料。需要公司价值判断时，经营到股东经济、估值与价格要求属于研究责任；仅针对经营问题的委托不强制追加 DCF。[S20] [S21]

一次有边界的委托由研究者在已获准工具、访问权限及实际运行限制内自主推进。对可能改变本次判断、仍有合理推进办法的重要工作继续取证、计算、挑战与修正，不把它一律交回用户逐轮催促。用户已明确费用不作障碍，不能再用未给月费或臆测 token 预算停止；但平台中断、访问拒绝和真实不可得信息仍须诚实处理。阶段保存不是新委托，报告排版完成不是研究完成；不授权无限循环或另开后台模型平台。[USR]

**已验证基础：** 旧 #321 有新会话／新公司从一次委托自主推进的收口，#524 也保留了其他样本的深度不足。新项目继承可行能力与质量教训，不为证明这一点重研旧公司；新委托仍逐份检查它是否回答了真实问题。[EV07] [EV08]

## 13.2 经济结构先于情景

先识别足以解释结果的经济引擎：量／用户／产能、单价／抽成、收入、成本、现金转化、资本强度、融资与经济归属。披露分部与分析引擎可以不同，但映射有依据。不因披露表多而过度拆分，也不把不同业务强行压成整公司一个增长率。

检查引擎间的替代、共用成本、交叉补贴、资金迁移、共同客户、营运资金、产能及管理约束。变量能够分别变化不证明统计独立；联合世界要容纳旧业务衰退而新业务增长、收入增长而现金变差等合理组合，不先填三栏悲观／中性／乐观再寻找故事。[S22]

## 13.3 证据、竞争与财务诊断

对关键问题建立“来源实际观察 → 机制与适用条件 → 推断／假设／计算 → 集团或每股结果 → 最强替代解释 → 判别证据”的链条。公告里的计划、已报告数字、卖方预测、同行结果与分析假设分别使用。

按经济对象选择竞争、周期和商业化镜头。区分终端需求和补库存、暂时供给受限和持久优势、价格侵蚀和规模效应、认证／良率／资金／需求瓶颈。正常化盈利需要持续期与量价资本依据，不默认回到历史均值。

财务阅读按公司历史和披露范围争取有用跨期资料，原方法约五年／八季度是参考而非准入门槛。关键不是算够比率，而是利润解释是否被应收、库存、应付、资本投入、现金和债务支持。累计转单季、重述、并购、汇率和重分类先核可比性。[S21]

## 13.4 股东经济与可复算模型

先选择企业现金、权益现金或分红等分析对象。分部回到集团时核抵销、总部费用、税、利息、少数股东、权益法和股本，不把集团全部利润归一个股类，也不重复扣成本。

研究中可以复用成熟现金与估值方法，但算式必须与所用财报口径一致。从已报告经营现金流出发时不能再次机械扣除已包含的营运资金变化；增长预测需承担必要再投资；借款和增发不是经营创造的自由现金；每股结果反映融资和稀释。维护与增长投入难分时保留范围和敏感性，不伪造分部资本分摊。[S21] [S23] [O09]

模型输入绑定证据或明确声明假设，保留单位、主体、期间、范围和计算版本。确定性计算生成可重建结果；模型叙事不充当计算证据。报表、集团结果、每股单位与最终中文金额同时勾稽，防止比例正确但量级错误。

### 数值从来源到展示的防线

原 `claim_audit_contract_v1` 已有 Decimal 确定性重算、操作数来源绑定、证据字段值匹配和声明数值覆盖，且有对应错配反例。新项目先提炼合适原语；这不等于整套旧 Claim Audit schema 必须迁移，也不证明任意正文已被自动审核。[EV16] [EV17]

保留承载重要计算的原值、单位、换算比例、主体／期间和来源位置。单位换算、关键表格和计算结果由确定性代码生成，中文展示尽量复用同一已核数值，避免模型再次手工缩放。这里只约束重要数值的真实用途，不将所有正文数字都拆成独立数据库对象。

同口径 Relay 数据可作核对线索；跨主体、跨期间、总额／每股或报告／预测不能直接比较。差异保留双方依据，不能自动认定 Relay 是唯一真值。确定的单位、算术或引用矛盾阻止相依数值用途；原始资料和部分研究仍可保存。

不采用证券 Quick／Full 一律必填五项锚点及通用 ±15% 拦截。该阈值没有本项目依据，也无法发现锚点以外的正文错误。只对真正依赖的数值进行可解释验证。[REV2] [S08]

### 研究可恢复、模型可复算与价格刷新分开

自由底稿、计算脚本和主报告可以归档，但后台不会直接执行研究者提交的任意代码。需要自动价格刷新或 Odds 时，通过第 14.5 节的可选 `valuation_spec` 将产出接到复用或局部提炼的条件／Odds 算术；保留结果语义和必要保管，不强行构造旧研究类型，不设计第二套等价算术引擎。不提供该载荷也不阻碍有用 Full 留存。[EV13] [EV14] [EV15]

研究中新增网页、PDF、表格或摘录按第 6.5 节进入同一来源接收合同。原件不可保留时明确保管级别，不能把网址、模型转述或摘录升级为完整原文。

## 13.5 外部参照与真正的挑战

外部参照按相似经济机制、起点、阶段和期限选择，保留失败、成功、未成熟与遗漏；少数成功同行只是类比，不是概率基准。没有可用参照时说明检索范围与其他约束，不强造行业成功率。

挑战必须影响取证、模型、范围或结论，或有证据解释为何保持不变。保留竞争解释，不靠角色投票确定真值。独立审阅与同上下文自查分开；无需为了形式制造固定多轮或另开多个 Agent。[S21] [S23]

## 13.6 独立估值、预期对照与反推

主动比较市场预期之前保存经营判断及已知市场信息暴露，不自称完全市场盲。估值方法和关键参数独立论证；选择何种倍数、折现率、持续期、资本回报需有经济依据，不为贴近市场价格倒调模型。

再比较有时间、机构、对象和目标期间的外部预期。预期差有证据才使用；价格要求是条件反推，不是唯一市场信念。基础业务、可选业务、利润增长与估值溢价不能重复计价。剩余价值重要时，继续反推可支持的未来利润／现金、经营规模、资本与时点，再折回与原价格相同的单位。[S23] [S24] [S26]

## 13.7 合理停止与部分成果

| 剩余工作的性质 | 应有处置 |
|---|---|
| 已取得材料尚未分析 | 优先完成有判别力的计算／核对，不能伪装成等待未来 |
| 已披露但未取得／未核验 | 评价并执行合理获准查证；一次失败不等于资料不存在 |
| 当前公开范围无法识别 | 建立有据范围或限制结论，说明还缺什么 |
| 必须等待未来事件 | 留具体观测、时点、可能结果和重开条件 |
| 工具／权限／资源中断 | 保存已有成果，明确未完成及受影响结论，不签研究完成 |

问题已充分回答、被证据重构／否定，或者继续工作当前不能有效区分解释时，可以停止。无需消灭全部未知；关键缺口也不能被完整模板遮住。原委托各重要问题分别交代，不能只完成几个子问题就宣称整项 Full 完成。[S20]

## 13.8 Full 成果与后继

成果包括主报告、关键证据引用、计算与假设、具体挑战及处置、范围充分性说明、未决问题、复核条件和前驱关系。可采用少量文件或结构化记录，不规定六个 Agent、六次调用或六份底稿。中间成果可保存，冻结版本不等于研究真理、人工接受或 Odds-ready。

价格单变只更新适用计算；新证据定位受影响假设；方法／单位错误形成勘误；期限滚动不是单纯价格刷新。Full 中得到支持的公司关系和跟踪变量供后继 Quick 使用，未核关系仍为候选；无需重新反向从报告全文猜出所有合同。

## 13.9 不同经济对象使用不同研究镜头

成熟非金融公司侧重现金转化、再投资与持续期；周期公司区分价格、供给、库存和正常化资本回报；转型公司检验旧业务负担、新业务商业化及融资约束；金融企业不能机械照搬普通企业现金流桥；研发／项目型企业按阶段、权利归属、投入、里程碑和有依据的条件世界研究。

这些是方法选择，不是固定分类器。缺乏可识别参数时，Full 可以给限定范围、竞争解释或不支持价值结论；不能因估值困难停止仍有价值的经营分析，也不能把其他公司成功率搬来补概率。适用镜头在研究成果里说明理由，后续有证据可调整。[S21] [S22]

## 13.10 Full 的首版交付边界

新产品可使用有限真实资料和所需合格市场输入，先完成直接 Full，不等待所有 Radar、全部来源或 Decision 完成。首个可用产品必须有一份在新入口实际完成并可接续的 Full；它同时检查新来源接收、产出保存和后继使用，而不是重新认证“GPT 是否会研究”。

继续既有经济问题时复用仍适用分析，只重开被证据、口径或方法变化影响的部分。不要求用户补研究轮次口令；真实中断就保留未完成，不承诺对话外未经配置的后台工作。

<a id="chapter-14"></a>
# 14　估值、Odds 与多期限机会表达

## 14.1 三种分析资格不能混用

| 类型 | 输入与输出 | 边界 |
|---|---|---|
| 条件情景分析 | 明确研究／经营世界、声明价格、期限 → 每个情景的条件结果 | 可无概率；不生成加权收益、胜率或伪期望值 |
| 临时／人工价格试算 | 固定研究＋Human 提供的价格 → 对应敏感性结果 | 人工价不升级为合格行情，不冒充可执行报价 |
| 合格数值 Odds | 精确冻结研究、满足政策的概率与风险输入、合格行情／期限 → 确定性结果 | 缺任一关键资格只限制该数值用途；不为了通过而补参数 |

计算器不隐式抓取行情、更新研究或创建 Decision。收益需标明累计／年化、名义／其他口径、币种、费用／税／分红是否纳入。概率和模型风险未建立时保留未知；先复用原确定性实现并以新合同校验，不照搬旧阈值作为普遍投资政策。[S01] [S20]

**原范围已成立：** Research-only 不依赖行情、没有概率可以保留条件研究、人工价格不升级合格 Market、数值冻结研究只换价格的机械正例与无概率真实价格拒绝例均有依据。保留原限定，不为取得无条件 PASS 捏造概率或恢复已退出案例。[EV07] [EV14] [EV15]

## 14.2 价格条件与研究有效性

每个结果绑定 Research 版本、价格 ID、报价时点、计算方法、期限和政策版本。用户给出的价格只作为其声明用途的上下文；来源失败可以展示旧结果原日期，但不能伪装成最新 Odds。新经营反证触发相关研究复核时，旧结果可保留历史，不继续无提示地呈现为当前有效。

估值参数变化、概率修订、股本／公司行动变化、期限滚动均要说明原因。只换价格可以重算；改变其他假设不能以“刷新”隐去研究修订。

## 14.3 Opportunity 的完整表达

Opportunity 不单回答公司好不好，而回答为什么现在值得看、可表达在哪个证券／方向、依据是什么、价格条件怎样、何时可能验证、最强反证和失效条件是什么。它可以是值得研究的线索、观察中的假设或已有研究支持的条件机会，不要求直接给投资建议。

区分经营兑现时钟、市场预期变化时钟和价格／流动性表达时钟。短期事件窗口、较长经营研究期限与实际持有打算分别声明，不能用一个“20日”覆盖所有意思。期限由案例决定，旧 D 的 5／20 等例子不是全局常量。[S12]

## 14.4 催化剂、预期与未知

没有明确催化剂可以保留机会，但时间成本和待验证条件要清楚。公司指引、券商预测、市场一致预期和价格隐含条件分别保留来源角色。公布后的价格反应必须使用公布后的合格交易时段，不能拿事前收盘涨跌解释盘后事件。

没有证据时不写“已充分定价”“预期差确定存在”或“利好出尽”。研究者可以提出解释与反例，标为假设并跟踪，而不把市场叙事升级成事实。

## 14.5 计算产出合同：可选 valuation_spec

只有准备由后台执行条件计算、价格跟踪或数值 Odds 的研究，才提供结构化 `valuation_spec`。它是 Hosted 成果到受支持计算的受限产出合同，不预先认定适配工作必然很薄；不是通用表达式语言或任意脚本执行环境，Full 保持复杂、自由的内部模型。

先列出新研究输入与旧计算输入的实际差异，再确定复用到哪一层。旧 `FrozenConditionalWorldSet` 的构造／核验依赖已提交 `ResearchSnapshot`、研究信息／全文哈希、Evidence／ValuationBasis ID 及期限；旧条件 Odds 构造明确只接受 `HumanPriceContext`。这些是旧适配合同，不是新研究必须兼容的模型。[EV14] [EV15] [ODDS-SRC]

| 旧实现部分 | 新项目处置 |
|---|---|
| Decimal 精度、归一化、每股分配与条件收益算术 | 能直接复用就直接复用；有旧类型依赖则在必要范围原样提炼，沿用适用正反例 |
| 币种、现金日期、期限、分配与终值不重复等约束 | 保留语义，由新输入／结果合同继续承担 |
| 旧提交状态、信息哈希及旧 Evidence／ValuationBasis 绑定 | 不模拟旧快照；以真实新 ResearchRevision、SourceRef 和计算依据关联承担相应责任 |
| 人工参考价与 Relay 合格行情 | 保持来源与用途区别；不能把 Relay 值伪装为 HumanPriceContext 以通过旧入口 |
| 新产出到后台计算 | 根据依赖选择直接复用、窄适配或局部提炼；不另造等价算术，也不保留永久旧 schema 转换层 |

**禁止为了调用旧类而拼一份“已提交”的虚假 ResearchSnapshot、补造旧哈希／证据 ID 或强迫新研究维护旧状态。** 新项目不承诺读取旧序列化载荷，也不因类名复用继承旧政策阈值。B0/B1 只识别首批研究确实应留的币种、价值时点、期限、股本／现金口径与来源；B3 自动计算启用前完成新边界适配。此工作不阻断 B2 正常 Full 的自由研究与可靠保存。[EV13] [ODDS-SRC]

载荷绑定研究修订、证券／股类、币种、价值口径、估值时点、未来期限（适用时）、情景产出或区间、分红／现金流处理、固定资本结构、计算方法版本和允许变动的输入。实际概率和风险资格没有建立时留未知，不能默认等权。金额口径与每股分母明确，重复现金／股权价值不可相加。

**今天的估计公允价值**只能支持折溢价／估值距离等相应用途，不能直接冒充未来持有回报。**未来某一期退出价值及分配现金**可以在声明方法下计算条件累计收益；年化、费用、汇率或期间现金流只有方法明确支持才计算。两者都不是已识别的市场真实信念。

“只换价格”只允许变动载荷声明的价格输入，结果另记实际价格日期；不暗换股本、净债务、概率、现金路径、终值或估值期限。入场日期变动不滚动原目标日期；不具备相应期限算法时不自动年化。公司行动或新证据需明确调整／新载荷，并保留前驱。

不支持的模型允许保存，但返回“后台计算未支持”；关键输入缺失仅限制其计算。既有两价格正例与无概率拒绝例直接复用其规则和适用测试；新增载荷／来源接线才补对应离线重算及币种、股类、期间、分母错配反例，不重做真实公司研究或新模型调用来演示同一算术。[REV2] [EV15]

## 14.6 结果保管与当前用途资格

原结果留存已区分 provisional、同研究比较和无概率条件结果，并能绑定同研究重建。新项目沿用这层区分，将序列化与新存储接线限制在必要范围；不递归带回全部旧档案解码器。[EV13]

读回历史计算只证明当时载荷可以恢复，不刷新当前来源／研究资格，不推断人工接受。普通条件计算没有概率时，当前合格价格可以改善价格输入，但不能凭此产生概率加权数值 Odds。

<a id="chapter-15"></a>
# 15　Attention、Watch 与交付

## 15.1 注意力不是投资信心分数

建议由一个注意力政策组织三类队列：值得探索的新问题、已有研究需要复核的变化、用户明确待回应事项。运行告警单独呈现，避免把采集故障包装成投资事件。

排序依据可包括新颖性、潜在经济重要性、与现有问题的关系、事件时效、证据质量和调查成本。解释优先级，但不将不同维度压成无法解释的单一投资评分。低确信度、高判别价值的问题可以值得优先调查。

首屏配置少量重点，单次交付保留实际选取与必要省略理由，不为全部输入或模型内部想法逐项建行。机械扫描范围按第 7.4 节记录，Quick 保留实际成果而非仅事后赢家。未展示不等于拒绝；用户暂缓关联具体问题／版本，不能屏蔽该公司所有新反证。[S08] [S24]

已有 Full／后继研究进入 Quick 和 Brief 的自然采用，以及单位勘误记录，是本版继承依据。接续已发生与其仍有质量缺陷同时成立；新平台只检查新入口和受影响输出链，不因一项错误将全部交付能力归零。[EV09]

## 15.2 Watch 的目标合同

按用户 2026-10-20 在 [#60](https://github.com/auguspp/Decision-OS-2/issues/60) 明确的用途，默认 Watch 接续公司级 Full：一条线跟踪已形成 Odds 对应的价格条件，另一条线跟踪 Full 尚未解决且会影响 Odds 的关键问题。Quick 的发现线索继续进入研究议程，不自动成为默认 Watch。Full 正常交付时应核对这两类接续，不反复要求用户重新解释监控对象；实际登记、启用和运行仍分别留证，报告保存本身不证明这些步骤已执行。

Watch 绑定确切 Full／Odds 版本、对象、变量、条件、所需数据资格、检查频率或事件窗、允许效果及结束条件。关键问题须说明会改变哪些价值输入或情景，不能用“研究版本变了”替代经营事实的变化。没有实际可用的 Odds 或价格边界时，只跟踪有依据的关键问题，不补价格阈值、概率或人工接受。具体实现与历史合同见 [Full 后持续 Watch](research/full-watch.md)。

结果区分未启用、计划未到、实际检查、条件未满足、首次触发、持续触发、无法判断及已结束。数据缺失不是未触发；日程到期不证明事件发生。触发后的动作可以是提醒、更新研究议程或执行已授权确定性重算，不自动开展 Full 或投资行动。

Full 后 Watch 持续观察；首次触价、Brief 已采用或用户暂缓回应不自动终止它。各价格档及关键问题保留各自的持续、离开、重入和未知间隔；有限执行批次用完不等于用户不再关注。研究／Odds 被有效后继替代、原前提失效、固定经济期限到达及明确停用须分别处理，不能静默延长旧模型或删除历史重开。

用户已同意：在原 Quick／Full 委托和任务范围内，重要问题、经营变量与复核事件可自动加入同一内部研究议程，供后继 Quick 参考，不逐项再确认。新 Full、新定时任务、主动提醒或通知频率不因研究保存自动启动；提醒类别可以一次明确授权后按规则执行。费用非约束不等于工作范围无界，阅读一家公司本身不登记对外通知 Watch。[USR]

## 15.3 迟到、重复和通知一致性

同一个条件持续成立，不每天伪装首次触发。条件更新、实质新证据、到期复核或人工重新开启有独立身份。事件、研究更新与通知使用关系而非公司名称去重。

跨系统不承诺“恰好发送一次”。建议先事务性记录待交付意图，再通过获准通道发送并登记回执；返回不明则对账，不盲目重发。具体实现可复用数据库表和现成调度，不引入通用消息平台。消息生成、保存、通知、用户阅读／回应分别留证。

## 15.4 Brief 与晨报

Brief 读取实际完成的 Quick／Full、来源观察与用户反馈；引用确切版本、实际截止和采用／省略关系。来源新材料未被研究时可作为“新观察，待解释”交付，不为了等待分析隐藏重要事实，也不自行补因果。

用户已选择 Watch 结果先进入既有 Brief。正文应接续原 Full 和实际检查，呈现新的价格触界、影响 Odds 的关键证据变化及重要未知；持续同一状态不每天包装成首次，复核状态不因没有价格触界而被省略。Brief 的原研究采用可以包含 Quick，但这不使 Quick 获得 Full 后 Watch 的资格。正文采用、独立读回、用户已读与正式决定分别成立。

晨报对照实际晚报正文，不拿计划时刻或 last_run_time 代替。晚到研究在后继中以原时间接续，跨周末仍保留；没有取回比较基线时限制去重主张。短报合法，空白信息源不等于市场安静。[S08]

## 15.5 在途状态只展示实际证据

Brief 有真实启动回执但尚无完成结果时，可注明“已开始，尚未取得完成成果”；只有日程时，写“截至本次截止未取得成果，执行状态未确认”。计划启动时间和合理耗时窗口不能证明正在运行，真实平台状态也按其实际含义引用。

已完成且零候选、任务未配置、读取失败与成果未交接分别表达。迟到成果进入下一次获准交付，但本稿不承诺额外后台补发；不为展示状态新建心跳／轮询平台。只有后继正文真的采用，才记录采用。[REV2]

## 15.6 复用条件和交付，新增权限另外处理

旧价格 Watch、用户暂缓不重复催办、研究日历和已有交付范围提供可复用语义。Relay 接替原价格用途、内部议程自动化和新主动提醒才是变化点，不默认迁移旧 Watch 配置。[EV05] [EV10] [EV24]

既有渠道与实际受信回执可继续使用；拟新增的发送意图记录只在真实通知接线需要时落地，不为每次摘要建设消息系统。原暂缓只对应具体问题与条件，真正新反证可再次进入 Attention，但应说明变化。

<a id="chapter-16"></a>
# 16　Decision：完整设计，专门建设后序

## 16.1 产品目标与不纳入内容

Decision 帮助用户把经济判断、价格条件、重要不确定性和自己的明确选择关联起来，并留下可复核的当时记录。它不是系统自动替人决定，不是 Portfolio，也不要求接入持仓。专门工作台和流程可在发现／Full 闭环之后建设，但数据关系、权限、生命周期和验收在本稿中完整定义。

不建设自动交易、账户同步、仓位算法、组合优化或默认成交追踪。用户未来明确陈述的某次执行事实可作为可选关联备注；不反推完整持仓，不把“决定买”当“已经买到”。[S25]

## 16.2 五种行为必须分开

| 行为 | 记录什么 | 不能推断什么 |
|---|---|---|
| 研究选择 | 继续、委托 Full、暂缓、停止研究 | 不等于买卖意图 |
| 研究／方法接受 | 接受哪个精确版本用于什么范围 | 不自动接受后继版本、概率或投资决定 |
| 决策准备 | 对照证据、条件结果、替代行动和未知 | 不是 Human 已作决定 |
| 人工投资决定 | 明确选择、当时理由、约束、版本与评价期限 | 不等于实际成交，也不产生系统执行权 |
| 后续复核 | 新事实、条件变化、原选择是否继续或被替代 | 不重写原选择和当时可知信息 |

“有意思”“研究我同意”“可以合并”“继续”不能自动归类成投资决定。用户提出买价问题也不是交易授权。人工原话和用于导航的规范化摘要分别保存；有歧义时先存待确认草稿，不代替用户补意图。[S25]

## 16.3 决策准备包

准备包固定目标证券／表达、当前问题、Research 版本及主要假设、最强反证、行情时点、可用 Odds 或条件分析、期限和关键事件、尚未建立的部分、合理替代选择及需由用户裁定的事项。可以比较参与、等待、放弃或继续研究，不要求所有选项都有数值概率。

完整但未知的说明优于伪精确。没有概率只限制数值加权，不自动剥夺用户作判断的能力；没有合格行情时可以研究长期条件，但不能显示为当前可执行报价。没有持仓与总资产上下文时，不输出完整组合适配、可承受亏损额或仓位建议。

## 16.4 决定记录合同

记录真实人工确认、对象与选择、用户声明的决定时间、实际记录时间、研究／机会／价格／Odds 版本、已陈述理由与约束、适用条件和复核事件；没有说出的内容保持未知。记录可追加替代关系，不重写原选择，也不从讨论或成交记录反推投资意图。[S25]

**用户已接受正式 Decision 多一次独立明确确认。** AI 侧只提供 `propose_decision_draft`，提交草稿并返回待确认对象。正式确认不由同一 AI 写权限一步完成，不接受模型自行填写 `actor=human`、确认编号或一句原话作证明。[USR]

优先设计轻量已认证确认页：用户看到具体对象、选择、条件和引用版本后执行明确确认；确认绑定实际草稿版本或内容摘要，重要内容改动使旧确认不可继续适用。普通浏览／链接 GET 不产生确认。只有实际平台提供可验证、绑定本次内容的用户批准凭据时，才可用它替代独立页面。[O12]

签名链接、CLI 或 GitHub 评论不天然独立：如果同一 AI 也持有最终确认凭据或可以无用户动作执行该路径，仍不能代签。确认能力及凭据与一般研究工具隔离；回执由受信服务端生成并支持重复请求对账。

此确认只用于正式人工投资决定，不增加普通研究保存、委托 Full 或继续分析的逐次审批。专门能力上线前只保留草稿／讨论与研究反馈，不伪称已确认；决定时间未知不填保存时间，事后补记不冒充同期记录。

## 16.5 与 Watch、Attention 和 Research 的联动

人工明确等待某条件后，可以在授权内登记相应研究／决定复核条件；未授权则保持建议。条件触发产生复核项，不自动把 WAIT 改成 BUY。重要证伪信号出现后，相关旧判断不能继续悄悄显示为无风险有效；系统标记需复核，是否改变判断与行动由用户决定。[S24]

用户拒绝或暂缓的是一个具体问题和当时条件，不是永久删除一个公司。实质新证据、不同期限或新明确授权可以重新进入注意力，但要解释相对前次选择的变化，不反复制造同一待办。

## 16.6 结果评价

在决定时声明可用的评价期限和标准；不知道就明确未知，不能看到走势后挑一个最好窗口。后续分别评价经营假设、估值／条件结果、人工选择的一致性和有记录的执行偏差。价格涨跌不是充分归因；“判断合理但结果不利”“判断薄弱但结果有利”都允许。

不做持仓收益曲线，也能评价曾选择参与、等待或放弃的研究案例。没有实际执行与成本信息时，仅呈现观察价格路径与研究结果，不能冒充账户收益。[S25]

## 16.7 Decision 的验收与建设前边界

专门建设时验证：AI 只能拟稿；用户实际确认绑定具体选择与版本；伪造确认字段、仅打开链接、旧草稿批准重用均拒绝；重复合法确认可对账。研究接受不当决定、新版本不继承旧接受、决定不当成交；原理由和时间不被后见结果改写，条件变化只产生相应复核。

Decision 尚未建设时，上游只保证研究与机会记录具备可引用身份，并允许保存用户明确的研究反馈。不能把空接口、一个按钮或文档中的流程声称为 Decision 已交付，也不能为了等 Decision 阻塞 Quick／Full 的独立价值。

## 16.8 旧决定语义和新确认机制分开验收

原项目已有研究接受、人工决定、价格条件与实际执行分离的材料和行为约束，可作为语义及反例来源，不迁移其业务记录。AI 草稿到独立确认的防伪、防重放及内容变更失效是新强保证，只在专门实现时取得证据。[EV33]

因此，不把旧确认文字当作新服务凭据，也不为了证明新确认机制重新讨论旧投资决定。该机制未交付只限制正式确认用途，不限制普通研究、条件讨论或内部议程。

<a id="chapter-17"></a>
# 17　Learning：按需复盘与分级扩展

## 17.1 学习目标与证据链

Learning 是相对独立的复盘用途，不是其他模块的通用执行框架。首版保留实际 Quick／Full、Brief 采用与必要省略、明确用户反馈、研究勘误及版本关系；复用这些已有产物，不记录私有思考、不为每轮建立完整归因账。

一次按需 Review 只需回答：当时的问题与依据、后来出现的事实、哪些判断得到支持／被挑战、可识别的错误与未决原因、值得采取的有限修正。可简短记录在案例中，不要求方法变更提案或八类字段全部填写。

| 等级 | 范围 |
|---|---|
| 首版必须 | 上述实际成果可读、明确反馈可关联、纠错不覆盖前驱；可做人工发起的复盘 |
| 后续按需 | 某类遗漏／误报评价、事先声明窗口的自然样本、方法比较 |
| 不默认承担 | 每次运行全链归因、全市场完整漏报率、自动概率校准、自我改写方法或偏好 |

缺少证据就保留未知，不能从事后赢家倒造当时的发现、选择或理由。新系统自己的保管与备份仍必须可用，不因 Learning 减负而删除。[USR]

## 17.2 错过与错误的分类

下表是实际复盘时可选用的解释框架，不是每个对象的状态字段，也不要求所有问题归入单一类别。

| 可能缺口 | 需要先核什么 |
|---|---|
| 覆盖／取得 | 当时声明范围、实际来源与缺失；未覆盖不冒称漏检 |
| 检测／理解 | 输入是否存在，变化是否识别，公司关系／经济机制是否成立 |
| 研究 | 关键问题、已取得未分析材料、计算或解释的实际错误 |
| 交付／注意力 | 成果是否保存、被读取和采用；不推断用户已阅读 |
| 人工选择／执行 | 只有明确表达和实际执行记录才评价，不推断持仓 |
| 未来不确定性 | 当时合理但后来不利的状态，不能只以涨跌倒判对错 |

允许多因并存或归因不足。用户追问不天然证明初稿失败，但原本可发现的关键遗漏需要承认；原结果有利也不替弱论证背书。[S21] [S25]

## 17.3 分母、删失与评估窗口

日常保存当时实际成果，不只挑成功者；没有产生的潜在想法不补造记录。机械扫描用已有范围与异常处置，语义 Quick 声明实际输入／搜索范围，不建设一份全市场“本来可能想到什么”数据库。

只有开展效果评价或声称准确率／改进幅度时，才建立该专项所需分母、窗口和可比性。窗口开始前声明，包含失败和未交付，不顺延到成功；未成熟样本留未成熟，同事件多指标或转载不当独立样本。无完整分母，不报完整漏报率；这是结论限制，不是首版必须补全所有日志的理由。[S16] [S18]

## 17.4 分层指标与方法改进

按实际问题选择少量观察：覆盖缺口、重复、交付迟到、无依据断言、重要遗漏、数值错误、有效修订或用户反复催促。不开一个综合“AI 智商分”，也不默认周期性自动审计。

实际做过概率预测且有足够可比结果时，才讨论校准。历史材料回放不能保证模型未带后来知识；前向使用记录和原截止仍有价值，不据一个赢家样例认证方法有效。

确认有实质缺陷后，普通修复按现有 Issue／PR 与相应权限执行；只有真正改变方法、范围或用户偏好时才形成相应变更。不存在“每轮 Review 必须给方法升级”的义务，旧结果不改写，未解决部分不伪签。

## 17.5 已有 Review 与比较能力直接复用

原自然采用审阅和金额纠错已经是有效的按需 Review；D2 的比较原语已有主体、期间、会计口径、零分母、范围与缺值处理。新项目先用这些方法处理实际问题，不重新做旧 Review，不建设新的全量评分引擎。[EV09] [EV25]

公司指引与实绩可比较不等于 AI 预测正确，多指标也不等于多独立事件。旧公式和反例是技术资产，旧业务案例不因引用而变成新产品状态。

<a id="chapter-18"></a>
# 18　AI 行动权限、工具与任务接续

## 18.1 已有执行能力是起点，不再从零假设

旧 Hosted Quick 已有 GitHub 研究读取、评论写回与独立读回验收，交互研究有真实文件写入和精确版本恢复，直接／正常入口跨会话接续有已收口样本。Full 自主推进与后继 Quick／Brief 消费也有实际依据。沿用这些能力，不创建新的通用 pilot、权限测试文件或重复公司研究。[EV02] [EV03] [EV04] [EV05] [EV07] [EV09]

原证据范围必须保留：评论写回不自动证明所有文件动作，交互文件写入不代签定时文件写入，既有 GitHub 通路不代签全新 API。后继局部失败也不能把先前成立的能力全部归零。发生变化时按第 20、23 章只检查相关差异。

确定性用例承担必要采集、保管、索引、计算和既有授权下的条件检查；获准 AI 宿主承担周期性 Quick、交互式 Full 与 Brief／晨报的实际研究和撰写。WorkBuddy 是优先工作台候选，现役 GPT 任务与 GitHub 接收通路在相应切换验收前保持原责任。不建设第二套模型 API worker、通用 Agent 调度或无限循环研究平台。[USR]

## 18.2 授权由角色、对象、动作和任务范围共同限定

下表是**目标行动权限**。已有任务规则与行为样例支持其起点，但并不声称旧连接器已经用独立凭据物理隔离所有角色。新接口承诺的服务端隔离，在该接口交付时验证；不得因此把旧研究通路再次设为不可用。[EV06] [EV10] [AUDIT]

| 执行角色 | 可读取的对象 | 允许的写入与执行 | 不自动取得的权限 |
|---|---|---|---|
| 采集器 | 本来源配置、获准端点、必要去重信息和本来源进度；不取得无关研究与确认凭据 | 提交实际内容／数值与来源回执；在保管成功后记录本来源进度 | 修改 Research／Decision；确定公司受益；新增来源或时钟；发投资提醒、执行 Full |
| 定时 Quick | 任务范围内的内容、合格数据、既有研究、议程、允许使用的反馈及交付；可获准跨产业公开查证，不限于预选股票 | 创建 Quick 案例与修订；提交新取得资料；追加反证、研究问题和同一内部议程；保存必要使用记录 | 覆盖 Full 正式修订；把 `kind=full` 当作委托；自动新 Full、新任务或主动通知；修改方法、CI、权限；确认投资决定 |
| 交互式 Full | 本次委托相关的获准资料、Quick／历史研究与反馈；在范围内独立取证 | 自主分析、计算、挑战与修订；保存 Full、来源与可选计算产出；续接原内部议程 | 静默改写原件；替用户接受研究或拍板；将一次委托变成新长期任务；修改生产代码、凭据或来源政策 |
| Brief／晨报 | 各自获准范围内实际保存的观察、研究、议程及反馈；晨报遵守其实际晚报读取范围 | 保存摘要、采用／省略关系及真实交付回执；沿已授权既有渠道交付 | 独立补造因果；重做 Quick／Full；改研究结论；增加收件人、渠道或频次；把发出当已读 |
| 确定性计算／Watch | 已绑定的研究版本、计算载荷、合格行情和实际启用条件 | 运行受支持计算，记录检查／无法判断／触发；在授权内登记复核或提醒 | 自动补概率，执行上传脚本，修改经营判断；将到价变成 BUY／成交；自行批准新 Watch |
| 人工 Decision 确认入口 | 待确认的具体草稿、选择、条件和版本化依据 | 在真实人工确认后建立、修订或撤回决定记录；保存独立确认依据 | 股票交易、账户同步、仓位管理；将浏览、沉默或研究认可当成投资决定 |
| 工程施工／运维会话 | 已授权工程任务及所需代码、设置和脱敏运行事实 | 在施工范围内改代码／配置、正常 PR 交付和相应运行操作 | 将工程写权限下放给定时研究；用资源授权改人工决定；擅自公开资料、删除旧服务或绕过实际拒绝 |

同一工具能执行，不表示所有角色都能用；相同用户账户下的工程会话和研究任务也不共享无限行动权。既有资源均可使用、费用不构成障碍已获裁决，不再逐次询问常规消耗；授权范围、隐私、破坏性操作和平台权限仍分别成立。[USR]

## 18.3 追加、修订和正式确认不是同一种写入

Quick 可以提出与 Full 相反的解释，但通过新的 Quick／复核记录引用原 Full，不能静默把 Full 改成自己的结论。获准 Full 可以改变 Quick 的问题结构，并保留其引用关系。

研究作者可在自己的委托与修订链内追加成果。并发研究各自绑定起点；当前指针变更需要显式条件写，不以最后修改时间决定真理。来源原件不原地修改；更正由新版本或勘误表达。保存新研究不自动继承人工接受。

研究反馈只记录真实用户表达，不把模型的“建议继续”写成“用户要求继续”。正式投资决定只能由第 16 章的受信确认完成。无相应实现时，允许草稿与讨论留存，但没有“已确认”快捷后门。

## 18.4 工具合同与强制执行边界

新服务依据受信连接、任务配置或实际委托绑定确定身份、对象范围与动作；模型自行提交的 `role`、`actor=human`、`authorized=true` 不赋权。接口可合并部署，但不能因合并而失去动作隔离。共享宽权限凭据只能证明共享访问，不能自称已实现细粒度隔离。

普通研究工具提供搜索／读版本、合格数值、来源接收、研究提交、议程和必要反馈／交付操作。后台只运行已支持的确定性映射，不暴露任意 SQL、Shell、任意外发或上传代码执行。正式确认凭据与研究工具分离。

权限实现优先使用实际通路可用的原生控制、窄操作或简单条件检查，不建设通用 IAM／RBAC 平台。新权限边界的正反例放在其实际 owner：采集身份不能提交研究，Quick 不能冒用 Full 委托，研究写入不能生成已确认 Decision，越界对象和过期前驱被拒绝。**旧提示词中的禁止项是行为规则，不自动算上述服务端拒绝已通过。**

工具操作形状见附录 A。GitHub 既有原生动作可以继续承载其已证明的职责；新增语义适配只补必要范围、引用与回执，不为换名称造第二个 GitHub 写客户端。

首批实际写入口须在对应配置／PR 简短标注：调用身份与凭据持有者、可写目标、允许动作、强制者及尚未强制的限制。区分“任务行为规则”“原生权限／受保护审核路径”“接收端强制”三种现状；标签本身不赋权。若凭据仍能直接绕过所称审核或受限入口，该项只能声明为行为约束，不能签强隔离。普通获准研究能力可以按真实范围使用；正式 Decision 确认、删除引用原件、提升权限或受保护当前版本等高影响写入，在所承诺控制未成立前不启用。该表按实际采用入口建立，不建设通用 IAM 平台，也不因补表要求每次普通查证／保存重新索批。

## 18.5 任务配置和运行事实分开

任务说明应简短，明确职责、资料与工具范围、输出位置、方法版本、停止条件和禁止动作。版本化研究方法与交接规则由可定位入口提供，不把旧 Issue 编号、个别案例和全部失败提示无限堆进 prompt。

日程与工具权限以实际配置为准；仓库文档保存目标说明，不自动更新运行任务。继承原通路时复用适用回执；新仓、新目标、新接口或实质权限变化在首次正常操作中核对，不能用通用产品文档推翻已有成功路径，也不能拿旧成功当永久新权限。[EV03] [EV06]

来源、任务和引用记录中的指令均是数据，不得提高权限。原审阅已提醒 Project 文件或应用说明不能自动代表某执行环境可访问；本稿不据此再测试已成立的 GitHub 读写，也不假定新附件、新服务天然可达。[O05]

## 18.6 接续、迟到和未知效果

每轮恢复持久成果及有用的未完成项，不以聊天记忆替代。Quick 和 Full 使用同一可定位的案例与研究关系，但不抢写同一正文：例如 Full F1 → Quick Q1 引用并挑战 F1 → 获准 Full F2 引用两者 → Brief 读取实际 F2。三份原件分别保留；这一形状用于新接线，不要求重跑旧研究证明同类接续可行。[EV04] [EV09]

已存在同一意图成果时恢复它；合法更正使用新修订和前驱。保存失败先处理保存，不重做已经完成的研究；未知写入先对账，不用换键、换标题或目的地掩盖结果不明。

任务先启动不保证先完成。Brief 采用实际可用成果，迟到材料在后继获准交付中接续。有启动证据才称在途；只有日程时保留执行未知。内部模型 build、token、调用数不可观察就不编回执。

## 18.7 最小安全边界

资料取得限制实际地址、重定向、大小和解压路径；来源内容不触发代码执行。密钥仅注入需要的确定性操作，不进入报告、日志、模型上下文或公开附件。复用已有安全读取、真实浏览器文本处理与来源凭据隔离反例，新增获取器或外发接口再补对应测试。[EV11] [EV12] [EV19] [EV29]

明确权限拒绝停止受影响操作；未知效果先只读对账；确定未发出的参数错误与可能已发生的写入分别处置。不承诺“模型绝不会受到提示注入影响”，而对关键写入、确认、执行和外发建立实际边界。某项新强隔离未实现，不自动否定原获准研究能力，也不能被描述为已经满足强隔离。

# 19　软件架构、目录与复用选择

## 19.1 推荐架构：模块化单体，按用例显式组合

一个主要 Python 项目承载领域合同、纯计算与后台用例；前端和工具宿主按实际需要存在。能力边界清楚不等于独立微服务。暂不引入通用 DAG、事件总线、动态插件、DI 平台或知识图谱数据库；不是永久排斥它们，而是当前没有必须由其承担的已证明问题。[S03]

按以下责任收敛，不先搬目录、拆仓或重命名包：

| 责任 | 保留的稳定义务 | 可替换部分 |
|---|---|---|
| 决策内核 | 对象／证据身份、前驱与重要未知、用途和时间资格、确定性算术、Watch 检查历史、人工确认边界、按需 Review | 供应商、聊天平台、页面和运行器不进入判断规则 |
| 版本化方法 | 经济结构、现金／资本、反证与合理停止，方法按 id／digest 可追溯 | 当前 Quick／Full 方法可经受信选择替换；不由 payload 自报批准，不执行上传代码 |
| 薄运行与连接层 | 动作范围、单一提交责任、幂等／CAS、未知效果对账、必要调度和恢复 | GitHub／CLI 及来源适配是当前接线；有真实需求才增加窄 API／MCP |
| 外围能力 | 获准信息取得、AI 执行、工作台交互和发现覆盖各有承担者 | 优先复用 WorkBuddy 与成熟连接器；替代前保持现役消费者及回退 |

普通 `RevisionInput`／`VersionedStore` 已可保管有权限的部分成果；指定方法合规、经济充分性、行情／概率资格与人工确认分别成立。默认 Full 的信息池／Relay 核查属于该方法的执行合同，不是所有成果保管的必要条件。方法替换也不能抹掉前驱未完成项或继承原方法的通过标志；实际已支持的操作与方法限制见[研究宿主操作映射](research/runtime.md#kernel-operations)。

依赖从核心向外：领域不依赖采集／GitHub／提示词；方法依赖必要领域值；观察转换不借发布模块；应用拥有一次用例的副作用和预算；基础设施实现窄接口；接口层显式接线。不为每个函数建立抽象类，也不让基础设施通过导入带执行的用例获取工具。

仅在首批需要真实 writer 和 reader 的地方创建代码与存储：来源接收、可查询的有限内容、研究修订与交付、必要身份和计算、原生工程入口。Decision、共享前提、高级历史查询等保留本稿目标合同，不预建空 facade、空表与动态发现框架。

# 20　既有通路、存储路线与增量验证判据

## 20.1 分开选择内容存储和研究工具入口

**现役起点：同仓 main 管工程、records 管获准资料与研究；外部获准宿主复用既有 CLI／GitHub 接收与读取通路。** 继承原 GPT↔GitHub 读写和接续的适用证据，不要求为了新架构图先放弃已工作的路径。本地镜像、页面和搜索索引只作派生，不竞争当前研究指针；本轮不迁库或建立第二研究主库。[EV02] [EV03] [EV04] [EV05] [EV09]

GitHub 不因此必须永久承担每条行情、所有资讯正文或全部原始字节。SQLite 目录、受控对象存储等仍仅是满足第 20.5 节实际触发条件后的候选；采用时向研究提供可定位的有限读取面。研究宿主是否直接访问新服务，是独立的接入选择，不是使用数据库的必然前提。

下列是**候选拓扑，不是已部署事实**：

```text
获准采集／人工输入／研究新来源
        │
        ▼
内容目录＋类型化数值＋获准原件
        │                         ┌── 获准 AI 宿主↔GitHub 通路 ── Quick／Full
        ├─ 有限、明确版本的读取面 ─┤
        │                         └── 新受限工具入口（确有用途时）
        │
        └─ 唯一归属的研究接收／索引 ── Brief／议程／计算／Decision
```

图中两种研究入口不是必须同时建设。首先选择新增维护最少且能满足首批研究的路径；只有实际查询、规模或保存用途说明必要时，才引入新接收器或服务。不得重建旧巨型 Collector、无限 Issue 研究日志或所有 Library 补丁链。

## 20.2 权威位置：按对象决定，不建双主

| 对象 | 启动期的推荐归属 | 其他存储的地位 |
|---|---|---|
| 代码、方法、维护配置 | 新仓 Git 主线及明确版本 | 安装产物、只读镜像 |
| 研究修订与有限案例入口 | 现役同仓 records，沿 VersionedStore 的单一提交与前驱合同 | 本地镜像／数据库只作派生，不独立改写同一研究 |
| 大原件、批量数值、内容目录 | 当前按已实现保管合同保存有限获准工作集；新介质须先满足实际替换条件 | 未采用的对象目录不成为第二真源；必要原件和恢复链不因减负删除 |
| 来源进度与执行效果 | 拥有采集／接收责任的用例 | 健康摘要不可反向充当恢复真源 |
| 交付记录与内部研究议程 | 随其权威研究／交付 owner 保存，明确单一路径 | 页面与搜索结果为派生 |
| 正式 Decision | 后序由受信确认 owner 保存；确认载体届时明确 | AI 草稿不是正式决定；普通研究写权限不能修改确认 |
| AI 宿主与确定性任务的日程／权限 | 各自实际任务配置，每项责任保持单主 | 仓库目标说明和已发生的采用回执 |

若改选数据服务作为研究权威库，须同时确定 Git 是投递区还是导出视图，明确唯一接收者和提交边界；不能两边都维护独立的“当前研究”。投递成功不等于已归档，索引存在不等于正文已读取。

同一套研究数据指同一权威对象与引用关系，不要求所有字节位于一个数据库。限定单写入者、研究分支与条件写的方案仍须符合实际通路能力，不能只在设计里声称 Git 评论已经具有不可变签名或数据库事务语义。

## 20.3 B0：证据继承与变化点确认

> **B0 以已有能力及原范围验收为输入。先说明启动路线相对已验证路径改变了什么，再为这些变化匹配最小检查。没有变化、已有等价证据的能力，直接继承，不另设 pilot。**

B0 产出是一份简短的路线选择及差异说明，不是新能力注册平台。附录 B 已完成 58 项设计层对账，不要求每个会话重新调查一遍。新仓尚未创建时，不能把“先向新仓试写”设成目标设计或基线收口的循环前提；新目标访问与首次写后读回在随后正常建仓／交付中完成。

### 哪些结论已有证据，哪些才需要补验

| 情况 | 处理方式 | 完成依据 |
|---|---|---|
| 既有能力、通路和适用前提未变 | 继承原范围验收 | 指明原证据和适用范围，无需额外试验 |
| 仅换新仓、路径、任务目标或配置 | 使用首次正常读写／交付核对 | 新目标实际可访问，返回定位正确，写后读回一致；不是重做研究 |
| 新增提交键、前驱选择、载荷或消费者 | 复用旧原语，仅验新合同 | 新冲突／失败反例和真实消费者接线成立 |
| 实际选用新 API、鉴权、中转或数据库 | 验证该新增接点 | 对应用途的真实持久化、接续及拒绝行为成立 |
| 原材料只有设计或测试定义，没有相应执行证据 | 先作有界证据定位 | 找到等价原证据即可继承；不足时只补当前用途所需部分 |

通过 B0 并不表示新仓 CI、中文全文索引、Decision 确认、长期可靠性已经通过。它表示所选启动路径有足够依据，没有未处置且会改变当前路线的关键缺口；后续具体接线有明确 owner 和验证位置。

## 20.4 增量技术验证的通过、失败和未验证判据

以下表仅用于**实际发生变化或缺少等价证据的接点**，不是所有项目必须重跑的全链清单。预期越权拒绝是权限测试成功；正常授权操作被错误拒绝则是不满足用途。

| 检查对象 | 通过条件 | 不通过／尚未验证的例子 |
|---|---|---|
| 新目标／入口 | 使用实际拟采用的连接，读到指定记录及版本，目标不串仓／串案例 | 只有链接、模糊搜索或旧目标成功；新目标访问尚未确认 |
| 新研究保存合同 | 结果实际持久化并返回可定位版本；首次正常交付可读回 | 只返回 200、自报成功或仅存于会话／内存 |
| 新跨环境接点 | Quick 读取 Full 引用，Full 能恢复 Quick 增量，后继 Brief 读取实际成果；旧路径未改变部分引用原证据 | 两个环境各写独立文件但无法关联；靠复制聊天正文恢复 |
| 新定时专属通路 | 在真实定时环境完成拟承担的读／写动作及后继接续 | 用交互测试代替；新增每次人工点击后仍宣称无人值守 |
| 新幂等／并发处理 | 同意图同内容返回原结果；同键不同内容和过期前驱拒绝覆盖；未知写可对账 | 盲目重发、换键制造重复、最后写入静默获胜 |
| 新权限边界 | 受信身份可做允许操作，越权动作和模型自报权限被拒绝 | Quick 伪造 Full 委托，普通研究写直接确认 Decision |
| 新持久化／中转 | 原件和索引一致；中断有明确结果；重新读取或恢复后仍能定位已确认成果 | 只验 Mock、不验实际归档；投递被当权威保存；两边各自改当前版本 |

结论分为四种：**原范围继承／变化点通过**；**明确不满足用途**；**存在正确性或权限缺陷**；**尚未验证或暂时受阻**。只记录实际证据，不为这些结论建立通用状态机。

正确性或权限缺陷（如丢记录、越权、覆盖新版本）必须先修复受影响路线。暂时网络故障或结果不明先保留并对账，不能立即升级成平台永久不支持。已有相同失败及原因时不重复试错采证；必要后继在实际获准工作中进行。

## 20.5 路线选择和备用判据

| 路线 | 采用条件 | 限制、备用与停止依据 |
|---|---|---|
| **G：继承 GitHub 研究通路** | 首批研究可由既有读取／评论或文件保存方式承担，新的路径和资料表示能够有限接入 | 直接采用旧能力证据；正常新仓操作核新目标。不能把评论写入扩称所有文件动作或任意新服务都已通过 |
| **D：直接受限数据服务** | 实际查询、数据量或写入用途说明新增服务必要，且相关执行环境的新接口通过第 20.4 节检查 | 只有新入口要验证。D 不成立不否定 G，也不迫使交互 Full 停止 |
| **T：获准投递通道＋唯一接收者** | 直接写回不满足用途，但存在独立获准的投递路径；中转的持久接收与后继可读已证实 | 已投递／已归档分开，只保一个权威写入责任。传输不是第二份研究真源，不作为绕过拒绝的包装 |
| **受影响自动化暂不启用** | 没有合法可用路线满足该自动化用途，或有未解决的关键正确性问题 | 保留具体未成立项；已有获准研究、方法与离线计算继续。不静默改成用户每天搬运，不另建后台 AI 替代已定方向 |

G 是有证据的起点，不是必须永远使用 GitHub 存储一切；D 和 T 是有明确收益才增加的候选，不因图里出现就同时建设。选择简单性、可靠性和维护责任，不再以费用不足为障碍。[USR]

**重新评估 G 的触发条件：** 跨案例检索反复妨碍研究；版本与来源关联长期需要人工搬运；并发修订／条件写成为实际负担；评论／文件／索引维护成本明显超过可行替代。引用丢失、受保护记录可被绕过覆盖或必需权限无法实现属于正确性／安全问题，应先限制或修复相依动作，不能只列入“将来优化”。无上述事实不定期重开架构比较。研究业务与计算不直接依赖 GitHub API，引用有稳定身份，记录有明确可读出方式和单一 writer；这已足以保留后续替换空间，不预建第二研究主库、双写或万能迁移器。

不得用 GET 包装写入、伪装只读标签、更换身份或外发目的地绕过适用拒绝。幂等只能限制重复效果，不授予执行许可。合法备用必须独立满足实际权限，不是对拒绝动作换壳。[O14]

## 20.6 宿主、调度和资源

现有资源均可使用，费用不是阻塞；实际访问、容量、安全隔离仍按相关用途确认。与 Relay 共机可以比较，但不能未核实就宣布充足、覆盖旧目录、破坏现役服务或向研究暴露凭据。代码仓实际为 public；本次设计归档不授予私人研究与运行材料的公开发布权限，实际数据位置在 B0 明确。[USR] [REPO]

选择单节点数据库时，按实际受控写入安排访问；不让多个主机直接争用共享数据库文件。SQLite 与必要对象目录是候选，不是所有研究的前置。采用其他已有成熟存储也须有实际用途，不为未来假想规模预建平台。[O06]

采集和确定性任务复用现成宿主调度或 GitHub Actions，各项责任只有一个执行者；研究由获准 AI 宿主负责。现役行情的单主外部 Cron 与其他已配置任务各守原责任；本轮不另开第二时钟、writer 或通知。写入与备份当前沿已验部署保持，不要求它们永久只能运行在 GitHub runner 或与 store 同机；替换须保留身份、权限、提交和独立恢复能力。时区显式，交易日历与来源口径由实际合格数据决定。新源不因代码合并自动采集，任务提示改动不自动增加调用范围。

有合理的请求、字节、解压、并发和持续时长限制以保护来源和宿主；重试也算实际调用，不因回滚退还。长网络请求不持有数据库写锁。费用非约束不能解释为无限循环、无界重试或无限保留。

## 20.7 保管、备份与恢复

引用且获准保管的资料长期留存；普通未引用正文可限期保存。期限数值在实际清理配置中明确，尚未设置时不擅自删除；被引用内容先核仍有效的保管责任。旧 Kernel／旧 OS 研究不属于新系统兼容或备份验收对象。

旧 Git／ZIP 保存与恢复经验可以继承；若采用新数据库和对象目录，须验证新介质的提交与恢复，不能以原读回代签。备份包含权威元数据、研究及需要的对象，采用存储系统支持的一致性办法；活跃数据库的单文件复制不自行宣布完整。主存储与备份隔离，敏感内容加密，恢复密钥不与数据裸存。[EV12] [EV13] [O07]

初始可采用日备份及主要读取在一个工作日内恢复的工程目标，但这些仍是待选配置和实测，不是用户已冻结的 SLA。重要成果可增加受控备份点，不建设多节点高可用平台。验收恢复后的引用、缺对象和损坏处理；备份任务绿色不等于恢复成功，长期保留不等于 100% 永久恢复。

## 20.8 健康、隐私与切换

健康分别呈现最近尝试、最近合格结果、来源日期、实际范围、待交付与备份恢复。旧成功不冒充今天，失败不等于没有研究成果；运维异常不包装成投资信号。日志保留足够定位但不泄露密钥与无关正文。

新旧切换按第 25.4 节明确 writer、在途效果、最后有效输出和回退。停用旧任务需要真实切换安排；文档重写不执行它。程序回退不撤销外部写入、通知和已发生费用，也不自动保证旧代码可以读新数据。

<a id="chapter-21"></a>
# 21　Issue、PR、AGENTS 与协作规范

## 21.1 信息归属与文档生效

README 负责产品与入口，AGENTS 负责按任务恢复和权限短边界，统一 principles 负责长期原则；engineering、ci、research-methods 各管自己的执行合同。ADR 保留重大取舍及替代关系，不给普通函数修复写一份架构宣言。

Issue 管有限问题与验收，PR 管本次实现与工程证据，运行和研究原件存各自业务记录。不要再让一个长期总 Issue 同时承担路线图、运行健康、每日研究和全部交接。当前正文应能直接说明现状，旧正文和旧 NEXT 不层层嵌套。

规则采纳、文档合并、配置更新和实际消费者采用分别记录。文档本身不产生新的运行权限；已由用户明确给出的现有资源／费用授权继续有效，不因某个技术细节仍为 PROPOSED 就撤回。[S01] [S02] [USR]

## 21.2 Issue 规范

一个 Issue 对应一个清楚、有限的目标；较大目标用父子关系组织，真实依赖另列。普通错字或现有范围的小修不必另开工单。调查可以以“不采用”结论收口，不强迫实现。

建议标题为 `[功能][content] 保留来源修订并支持按日查询` 或 `[缺陷][brief] 晚到研究未被后继采用`。标题描述稳定问题，不滚动写“最新完成第 N 组”。原生 Issue 编号是工作身份，不再创建第二套长期施工编号链。

正文应包含：用户问题／缺陷与证据、目标与非目标、能力／合同 owner 与消费者、验收、权限和副作用边界、复用或不做的选择、依赖／停止条件、当前 PR 与下一步。未知根因的 bug 可以先记录观察，不用填满模板阻塞报告。

建议只保留一套阶段标签：待澄清、可实施、实施中、待验收、阻塞、暂缓；Open／Closed 表示是否结束。正文解释事实，不另维护手工 status.json。父项进度不等于产品完成比例。

正文保留当前有效范围和短摘要；评论保留重大决定、失败、验证、交接和关闭理由，不每次查询 CI 追加流水账。范围变化用“原前提 → 新事实／指令 → 影响 → 处置”短记录，并同步当前入口。[S13]

## 21.3 关闭与权限

建议关闭“关联 PR 合并后自动关闭 Issue”的原生设置，让工程合并与约定的产品验收分离；实际配置必须读回。部分交付只关联 Issue，不用关闭词。纯代码范围的任务完成适用 main 检查即可关闭，不给每个小修附加自然观察窗；含使用验收的任务在其完成后关闭。取消、重复、被替代写真实原因，不标为交付成功。[O01]

编辑前读当前正文和相关 PR，写后读回。多会话冲突时保留事实重新对账；Issue 指派或评论不是可靠分布式锁。对 code head、当前研究指针等高影响写入使用条件写／期望版本，不能静默最后写入获胜。

## 21.4 PR 单元、命名与内容

一个 PR 一个可解释、可验证、可回退的完整责任组，包含必要代码、消费者、测试、配置、文档和旧责任退出。不一文件一 PR，也不长期滚动搭载后继功能。Draft 用于迭代，Ready 表示本组范围已收口；Ready 后修本组缺陷，不搭下一组。[S06]

建议分支 `feat/123-content-query`、`fix/124-late-quick-handoff`；PR／commit 使用 `type(scope): 实际改变`。已合并分支不继续承载新工作；永久模块不带施工号。

PR 说明必须足以回答：改变什么合同与消费者，复用了什么，新增／接替／退出哪些维护义务，实际运行哪些验证、绑定什么版本、尚未证明什么，以及回退与新数据可读性。模板是信息结构，不认证内容真实；网页和工具创建采用同一语义要求。[O02]

## 21.5 审阅、合并与交付

修改前查重并核在途任务，授权范围内不逐文件索批；现有资源与费用裁决不再重复确认。新的访问／外发权限、重大数据损失或暂停路径变化按真实影响处理。合并前核最新 head、base、diff 和适用检查；旧绿灯不验证新 head，自查不是独立评审。

完整继承 merge_reuse，建议新仓保留匹配的两父合并策略，并实际核 PR 与合并 tree。**两父合并本身不保证 tree 相同**，base 前进时可能合入其他变化；不满足复用条件则执行新 full。更改 squash／rebase／merge queue 策略必须同步验证结果资格，不能仅凭提交形状复用。[S04] [O13]

合并后按本次用途核 main、安装、发布、固定读回或真实消费者。回退代码不撤销外部请求、研究、通知和费用；新数据能否读取单独验证。PR 是交付单元，不是持续授权范围内强制停止单元。

## 21.6 工程任务与 Full 委托分开

建设 Full 工具、保存接口、方法或提示规范属于工程／方法 Issue 与 PR；执行一次 Full 属于研究委托，不为每份底稿或每次查证创建工程票。研究文件保存可使用 Git，但其合并只说明文件变更，不证明研究充分或人工接受。

交接只保留目标与授权、分支／精确 head、已提交与未提交、实际检查、未知／在途效果及定位、下一步和停止条件。接手从 AGENTS → 当前有限 Issue → 实际 PR／代码／必要运行事实 → 相关合同与教训，不每次重读全仓历史。[S02]

## 21.7 继承证据进入 Issue／PR，不变成第二套档案

相关 Issue／PR 简述“已有证据及范围 → 本次变化 → 实际补验”，可直接引用本稿附录 B 的条目与原来源，无需为全部旧记录回填模板。原生子事项、依赖提案、安全扫描、签名与正常交付能力已有实证；新目标只在首次实际配置／交付时核对应差异。[EV27]

权限不足、未暴露工具、尚未尝试和结果未知要分开。恢复已经工作的路径后执行真实所需操作，不每个会话先造测试文件；现存明确拒绝不得绕过，旧失败也不能成为永久不可用标签。[EV03]

构建新包、运行源测试、更新生产任务属于各自实际范围；只写目标文档不触发这些操作。普通工程验证不要求先完成产品自然观察窗；新产品验收也不能只看 PR 已合并。

<a id="chapter-22"></a>
# 22　完整 CI、测试与验证责任生命周期

完整体系已有实现、运行与交付记录，用户已经决定首日起继承。新工作是移植必要实现、重绑新仓与实际测试集合，不是再次研究四 scope／4×2 可不可行或值不值得做。[EV26] [EV27] [USR]

## 22.1 同时保留两类身份

**责任身份：** 哪项能力／合同受到保护、由谁拥有、支持什么、什么情况下退出。**结果身份：** 哪个仓库、代码／tree、运行／attempt、环境、测试集合、策略和产物被验证。Issue 关闭不等于能力结束；增加一个测试必须能说明它保护谁。

责任可通过模块、测试组和 PR 处置表达，不建逐断言登记平台。能力退役同 PR 处理其专属 workflow、test／fixture、依赖、缓存、配置和文档例外；共享 PIT、权限和数值保护迁到仍负责的 owner，不能连带删。[S04] [S07]

## 22.2 用户裁决：首日完整四 scope 与双级并行

| 范围 | 执行与资格 | 不可替代的边界 |
|---|---|---|
| content | 可信 base、精确差异资格和内容检查 | 方法／任务／权限／schema 的 Markdown 变更不自动豁免 |
| draft_feedback | 授权 Draft 的固定 smoke 和有限快速反馈 | 不是完整受影响集合，不能用于正式合并 |
| full | 当前完整 collection，独立合同组＋剩余分片，适用产物核验 | 任意一组或最快分片不能代表全部 |
| merge_reuse | 合格 PR full 与合并 tree／环境／策略严格对应，main smoke 实跑 | 明确是复用，不冒称 main 重跑全量 |

用户明确选择**完整优化体系**，因此四 scope、研究合同小环境、跨 runner 与片内 worker 的双级并行、集合／环境核验及严格 merge_reuse 均属于首日工程交付，不能再以测试少或评审减负建议将它们默认延后。[USR]

复用原生 workflow_call、pytest-split／xdist 与原有成熟实现；4 runner × 2 worker 是初始配置参考，按实际集合与资源校准，但不删除双级能力。小集合中的空分区应在实际声明集合内诚实处置，不制造无用测试来填片，也不将必要缺片标绿。新仓身份、测试集合、依赖和策略重新绑定；旧仓专属格式兼容及已退出业务验证不迁移。[S04] [S15] [O10] [O11]

时长仅作分配提示，未知时长测试仍须执行。每片实际 collection 与结果对应，片间互斥，并集覆盖声明全集；共享依赖版本一致，允许省包不允许无解释漂移。记录真实环境，不拿 prepare 环境冒充每个 runner 的实测。

## 22.3 最终 gate 与可信复用

根 CI 保留稳定最终 gate，核适用 needs、scope 和完整证据。必要 job 失败、缺片、取消或意外 skipped 不得被 always 汇总成绿灯。GitHub 官方区分 workflow 被路径过滤后 Pending 与 job 条件跳过后可能呈现成功，因此必须由自己的合格汇总语义处理，而不能只看一个绿色图标。[O03]

同 SHA 从 Draft 转 Ready 仍需正式验证；策略、依赖、未知变更不能自证免检。复用要求精确代码／tree、合并关系、环境、集合和可信原产物；不匹配时执行新 full，不放宽旧失败。新仓身份重新绑定，旧仓 CI 结果不能跨仓取得资格。

默认不以重试失败换绿；基础设施异常若有单独授权重执行，要保留原失败、原因和新 attempt，不伪装首轮成功。CI 无业务 secrets，读产物步骤与测试权限分开，不执行下载附件中的任意代码。

## 22.4 测试与产品证据分层

单元／合同层覆盖身份、时间、单位、算术、字段和资格；集成层执行真实用例与消费者；少量端到端样例覆盖采集、保管、恢复、读取和交付。模拟外部响应，不把待证明的 reader、预算、存储和组合责任全部替掉。[S10] [S11] [S12]

包外安装与 CLI、页面实际浏览器、定时环境读写、新上下文恢复、研究充分性和 Human 接受分别验收，不让普通 full CI 代替。Full 的证据／计算可机械检查，但报告章节齐全不等于研究质量。

## 22.5 Retirement First 与安全维护

先判断验证责任是否还应存在，再合并重复证明，最后优化执行方式。永久义务退出、同保护范围提速、真实新增回归保护分别计账；更多便宜用例不自动等于系统变轻。没有数量配额，不因测试年代或普通 import 为零就删除真实动态／人工消费者。[S07]

优先复用原生依赖更新、安全扫描和必要供应链验证，独立维护任务不无理由加到所有业务 PR 的门禁。依赖升级核确切版本、兼容和许可证；CI 工具自身也有退出责任。主线保护与 required checks 在实际新 repo 配置并读回，文档不是生效证明。

## 22.6 新仓启动与完整优化能力并存

新仓初期没有可信成功 base 或可复用的本仓 full 产物时，`content`／`merge_reuse` 的资格自然不成立，按其规则执行适用正式验证；不得拿旧仓结果代签或自造可信基线。代码与配置仍从工程起点交付完整四 scope 和双级并行，不把“暂时没有可复用结果”解释为该能力可以后置。

保留当前策略 writer／reader 的同一合同及必要反例，不为读取旧 Kernel 历史产物保留无用途兼容器。新项目自身后续产生的证据在其支持期内可读；不能每次改版就抛弃本项目有效引用。

首个正常工程交付建立新仓验证事实；后续一次真实 Draft→Ready→main 流程验证相应 scope 和复用，而不是另造业务改动或重复跑旧 benchmark。空分区、失败／取消／意外 skipped 和环境变化按现役语义明确处置，不填充无用测试。

## 22.7 防复发不是“所有边界永远再验一遍”

旧字段反例在其 owner 的合同层复用，跨模块只保留必要真实接线。新源码、依赖、路径或消费者变化仍跑相应正式 CI，但不重做旧来源请求、同公司研究或全体旧归档恢复。新增、接替和退役同组处置，继承旧失败形状不等于继承旧格式永久支持。

旧浏览器／CodeQL／Dependabot／签名能力有真实采用，复用现成配置与宿主；新源码和实际设置依其用途验证，不把首次扫描当长期零漏洞，也不把旧原生规则 403 当新仓永久限制。[EV27] [EV28] [EV29]

<a id="chapter-23"></a>
# 23　已有验收与经验教训怎样进入新设计

## 23.1 已完成的能力保持完成

上一轮计划验证对账按责任得到 58 项处置：21 项继承、19 项仅差异、7 项新增接点、4 项未证实、7 项取消。它们已经纳入正文与附录 B，不是新的测试数量或工作队列，不转换为开发完成率。[AUDIT]

| 处置 | 后续动作 | 不允许的扩大解释 |
|---|---|---|
| 继承 | 用原验收与实现起步，取消独立可行性重验 | 不用旧绿灯代签新代码或新目标 |
| 差异 | 确认改变的载荷、路径、存储、角色或消费者，只补相应证据 | 不把有新接线误称旧能力全未知 |
| 新增 | 对实际采用的新合同／保证做必要验证 | 不把所有未来新增接点全部堆到 B0 |
| 未证实 | 有界定位原证据，足够则继承，不足才补本用途 | 未找到不等于从未做过，不自动创建大专项 |
| 取消 | 删除首版不承担或无变化的重复义务 | 不借减负删除仍需的安全、数值和完整 CI |

## 23.4 同一个坑如何不再反复出现

关键教训由责任 owner 的代码／方法／工作流程承担，不靠每次长提示词回忆。再次失败先查：原保护是否未接入、输入范围改变、替身绕过、来源口径错误、入口未被读取，还是原规则不适用。修补真实原因，不只再追加一句提醒。

这次额外要防的是“忘记已经通过，再安排重复验证”。继承实施、成功验收和失败反例三类资产；未改变的事项可直接引用历史证据。相关 Issue／PR 只需注明适用原证据和本次差异，不建设能力注册中心、常驻探针或每轮全仓复习。[EV01] [EV03]

# 24　场景验收：继承证明，补齐变化

## 24.1 七个产品场景仍保留，不等于七项从零实验

完整产品必须能独立解释下列责任。验收采用“原证据＋本次变化＋正常新产品使用”的组合；能够复用的原证据不重新执行，未改变的机械规则随适用 CI 回归即可。旧业务状态不迁入新系统，不妨碍用旧成果证明技术能力已经存在。[AUDIT]

| 场景 | 产品应能完成什么 | 已有基础 | 本次只需补什么 |
|---|---|---|---|
| **A 价格与产业变化** | 合格序列→变化→产业／公司经济问题，说明关键缺口 | Relay 日常端点与实际使用、有限产业公司映射可复用 [EV18] [EV19] [EV23] | 新检测器、关系与内容池接线；期现货／规格／换月不混，不重新证明旧 Relay 用途 |
| **B 生活观察深化** | 人工观察→可验证假设→产业环节→实际查证 | 研究方法、有限关系与资料保管已有；新入口完整样本未证实 | 首个有真实用途的观察在新入口完成；不将 B 当作无提示发现 |
| **C 直接 Full** | 不经 Quick，完成委托相称的经济／现金／价值分析、挑战、停止、保存和恢复 | 单委托自主推进、研究独立保存、跨会话恢复均有原验收 [EV04] [EV07] [EV08] | 新产品正常委托检查新来源／载荷／入口及这份研究本身的充分性；不重研旧公司证明“能做 Full” |
| **D Full 到人工 Decision** | 研究与条件结果→草稿→受信确认→后续复核 | 核心条件计算、研究／人工决定语义可复用 [EV14] [EV15] [EV33] | 新计算载荷适配与独立确认路径；AI 代签、过期草稿重放、只浏览即确认均拒绝 |
| **E 迟到与局部失败** | 有用结果不因一族失败或迟到而丢失；后继可准确采用 | 真实 Quick／Brief 接续、原保管／归档失败案例与修复 [EV09] [EV10] [EV20] [EV21] | 新提交／查询／交付接点的相应差异；不重新制造生产磁盘或来源故障 |
| **F 后继变化与退出** | 实际有用的增加／替换／停用影响正确 owner，共享保护仍在 | 既有模块化比较与真实责任退出案例 [EV30] [EV31] [EV34] | 新项目第一次真实同类后继变化；不造无用功能或删减配额做演示 |
| **G 无具体提示的探索** | 无预选股票／事件／结论，在声明资料与获准范围内独立提出可核研究问题 | 已有自主 Quick 与行业观察，但是否满足新 G 条件须对齐 [EV02] [EV05] | 先选符合条件的已有自然成果；不足才在正常后继 Quick 留证，不另跑事后赢家实验 |

**首版仍须具有 A／B／C／E／G 的相应产品能力，不以 Quick 与 Brief 代替 Full。** 原范围证明可继承，新接线仍要在正常交付中成立。同一次真实工作可支持多个责任，但不是多个独立效果样本。

**G 的最小正向证据。** 事先声明真实可探索资料和获准范围，不由用户预选股票、产业结论或最终赢家；Quick 自行取得有来源支持的重要变化，提出可查证、可反驳的研究问题，解释可能经济机制与尚未证明的联系，并实际进入后继议程或正常交付。可以暂没有可靠公司映射，不为验收凑概念股；“新”相对已声明的研究／关注范围，不宣称用户从未想过或领先全市场。零候选可以是合格执行但不是正向发现证明，事后上涨不是必要条件。既有合格样例可证明原能力；新系统首次正常使用验证新接点，不把旧成果改日期当新发现，不另建盲测平台。

G 出现零候选可以诚实结束该轮；这证明没有硬编，不证明主动发现正向能力已经通过。一次正例也不证明普遍领先或投资收益。无法找到足够 G 证据时，明确标为相应产品验收未齐，不要求模型每天凑机会。

D 的完整设计现在保留，专门实现后验新确认边界；新 `valuation_spec` 只有进入后台用途时验证映射。F 随真正后继变化进行，不作为首个有用研究的前置工程。

## 24.2 证明层次与来源层次分别区分

合同／算术、真实消费者、工程 CI、正常发布、实际研究使用、独立上下文与人工接受证明不同问题。已有源资料可用于离线反例，但测试产物不能被标成当日生产行情；CI 完整通过也不证明经济解释充分。

原验收回执、真实任务正文、代码／测试、方法说明分别使用。方法写了某条责任不是它已验收，测试存在不是本轮执行，旧真实结果也不是全部工具轨迹。三层继承分别限定：旧算法／合同证明原算术与拒绝行为，不证明新输入兼容；旧运行证明旧目标上的可行性，不证明新仓／新权限已接通；旧产品成果证明既有使用案例，不证明新 Decision OS 完整交付。引用“原范围已验”时同时保留原来的限定，例如 RSS 无变化续作不代签自然新内容，数值 Odds 机械正例不代签任何当期公司资格。[EV15] [EV22]

确需自然窗口评价时，按实际问题事先声明范围、日期和停止点，保留失败与无增量；不无限延长到成功。新产品正常使用能够支持所需判断时，不再额外要求一轮相同“试运行”。

## 24.3 新功能的非功能责任

| 维度 | 继承什么 | 新项目需要确认什么 |
|---|---|---|
| 版本与一致性 | 研究引用、前驱、更正与原件非覆盖语义 | 新提交键、并发／当前指针和实际数据集引用 |
| 保管与恢复 | Git／ZIP 读回、严格库存、失败前缀等经验 | 实际选择的新存储及备份恢复；未选数据库不验证数据库 |
| 及时性 | 最近尝试／最后合格分开、迟到接续 | 新来源更新要求、新入口实际采用；不承诺每次准点 |
| 性能 | 已有 CI／采集／读取实测作原范围参考 | 新查询、存储和工作负载；不重做旧优化实验，不编 QPS |
| 可演进性 | 既有责任划分和退出经验 | 正常新包安装、真实第二次变化传播及新支持面的退出 |
| 安全 | 已有安全读取、密钥局部使用与文本不执行 | 新接口、确认、外发和实际新宿主边界，不作“AI 永不被注入”保证 |
| 可使用性 | 旧目录搜索、分页、浏览器测试宿主与独立接手 | 新全文中文短词／别名、页面和真实新入口；旧浏览器不是新手机部署验收 |

实际部署设置与权限属于具体目标，不能继承为永远开启或永远拒绝。旧 ruleset 403 与 Sites／实机未验只保留原事实，后续按新目标实际结果处置，不擅自绕过也不永久判无权。[EV28] [EV29]

## 24.4 验收记录只解释本次责任

记录本次改变、使用的原证据、实际执行及结果、尚未证明什么和下一步即可。不要求每个 PR 保存全量旧产物副本，不重复统计没有变化的历史，不为每个字段跑整链。

新产品研究质量逐份按真实委托审阅；方法整体效果需要可比后继样本。工程性能、运行健康、内容取得、研究充分性和人工选择分别报告。58 项处置数量不转换为完成率、测试比例、节省工时或投资能力分数。

# 25　建设顺序、切换与不兼容边界

## 25.1 目标先完整，实施按实际接点推进

## 25.2 候选建设序列与每阶段的证据责任

| 阶段 | 责任与产出 | 继承与收口方式 |
|---|---|---|
| **B0 证据继承与启动路线确认** | 以本稿和附录 B 为起点，选择首批研究读写／内容存储路线，明确实际新增接点与最小合同 | 继承 GitHub 研究读写、恢复、Full 和 CI 原范围证明；只补会改变当前路线的未知。新仓未创建前不强求向它试写，后续正常操作核新目标 |

阶段是责任排序，不是必须依次建完的隔离工程。B1 只要可用研究保存与必要资料入口成立，就可推进真实直接 Full，不等待所有 Radar、数据源或页面完成。B3 中已由旧能力承担的按需条件分析可以在 B2 使用；延后的是新自动接线和专门决定工作流，不是禁止用户提前讨论价值和价格。

B0 不部署一个与 B1 等规模的“试验系统”。已有路线足以支持起步时，可以结束路线准备；必要新 API 的测试只在实际采用前处理该接点，不连带重开旧 GitHub 通路。

## 25.3 白名单继承的是技术与证明，不是旧业务状态

用户已明确：**“原来 kernel 和 os 的研究不需要兼容了。”** 新项目不默认迁移旧研究、Decision、Watch、队列、旧回执、旧 schema、路径／hash、API 或历史 reader／codec，不为旧运行环境和全部旧案例提供执行式恢复。

白名单包括正确核心实现、成熟客户端／解析器、Full 方法、数值原语、完整 CI、真实故障反例，以及其原范围验收与运行经验。无需为了保留一个反例带回整套旧环境；可采用少量合法脱敏或等价合成输入。继承证明是设计和开发依据，不是导入旧公司业务状态，也不是把旧概率或人工接受带入新项目。

旧仓保留为技术参考，本次不删除、不批量关闭、不擅自停任务。新项目自己产生的记录按声明范围继续可读；以后显式导入一份旧材料按当次新接收处理，不恢复全旧格式兼容承诺。

## 25.4 新旧运行切换和回退

切换只覆盖明确职责：列出旧 writer、新 writer、实际资料目标、最后有效输出、切换点、在途／未知效果和回退办法。实际授权范围内进行一次正常接续，不让新旧长期对同一职责重复采集、研究或通知。

旧任务不能仅因新文档完成就停用。切换后旧源／任务的未来触发、专属权限、配置和验证责任同步处置；不删除共享保护。新数据读取与回退单独考虑，程序回滚不等于旧代码能恢复新格式，也不撤销已发生外部效果。

不以“证明停用能力”为由反复开关生产任务。可隔离验证的故障、冲突和停用首先使用保存／合成输入；新目标首次正常操作提供的证据不再重复演示。

## 25.5 对验证计划的明确删减

取消通用“GPT 能否读写 GitHub”pilot、为证明自主研究重研旧公司、重复独立恢复实验、原 4×2 优化对比、无变化的框架全审及每 PR 全仓复习。取消旧研究／旧环境兼容、全库 PIT 和逐轮 Learning 平台、首版全领域无遗漏证明。

# 附录 A　最小合同与协作模板

以下是评审级逻辑形状，字段名与最终类型尚未冻结，不是现役 API 或可直接部署 schema。先复用原语，再按实际接线确定表示。工具列表不是必须逐个独立发布的远端函数，也不能仅靠模型填字段取得角色、存储或人工确认资格。

## A.1 普通内容查询

```json
{
  "query_id": "<actual-query-id>",
  "scope": "<actual-source/entity/date/type-filter>",
  "items": [
    {"record_id": "<content-or-dataset>", "version_ref": "<exact-version>"}
  ],
  "observed_at": "<actual-query-time>",
  "next_cursor": null,
  "complete_for_query": true,
  "warnings": []
}
```

普通查询不强制历史知识口径或全库快照。`complete_for_query` 只描述这次声明的查询，不表示全市场、全内容池或所有潜在机会都已读取。确实需要稳定分页／批次比较时附有限结果集或数据集版本；新查证保留自己的取得信息。

## A.2 研究保存与候选修订

```json
{
  "case_id": "<research-case>",
  "submission_id": "<same-intent-stable-key>",
  "expected_predecessor": "<prior-revision-or-null>",
  "kind": "<quick/full/correction/continuation>",
  "scope_and_time": "<actual-research-scope-and-relevant-dates>",
  "method_ref": "<method-version>",
  "source_refs": ["<retained-version-or-explicit-limited-locator>"],
  "work_product_ref": "<actual-report-and-calculation-location>",
  "valuation_spec": null,
  "remaining_work": "<material-open-questions-and-disposition>"
}
```

`kind` 描述内容，不是授权；请求的受信任务／委托必须允许该动作。`expected_predecessor` 是本次真实起点，不允许从待覆盖对象中随意取一个“当前值”冒充已经基于它研究。并行草稿允许共存，当前指针变化另有条件检查。

部分研究可独立保存；没有概率、完整原文或 `valuation_spec` 不构成拒绝留存的理由。计算不支持只限制该用途。实际来源只能引用已取得的版本或明确有限外部定位，不能虚构已保管原件。

原生 GitHub 写入返回真实 comment／commit／path 等定位，再按相应通路读回。若新增接收器承诺同键去重、冲突拒绝和事务保存，须由接收器执行；不能把既有评论成功自动升级成所有新并发语义已通过。[EV03] [EV11] [EV12]

## A.3 保存与对账回执

```json
{
  "submission_id": "<actual-intent>",
  "result": "<saved/already-saved/conflict/pending/failed>",
  "record_ref": "<actual-record-or-null>",
  "version_ref": "<actual-version-or-null>",
  "custody": "<actual-custody-level>",
  "readback_ref": "<actual-read-location-or-null>",
  "limitations": ["<actual-limits>"]
}
```

回执由实际保存／接收端返回，不由模型预写。只有真的保存才给保存结果；投递与归档分开；未知结果不写成失败未执行。客户侧读回是另一个事实，不能在第一次请求正文中预签。

同键同内容恢复原结果；同键不同内容报冲突。对账应可以按原意图或返回定位查询，不以新键、新标题或新目的地避开不确定性。不承诺跨外部系统恰好一次。

## A.6 来源接收

输入包括原意图、来源定位、实际资料角色、资料日期／报告期／披露时间、取得信息及其依据、实际内容或文件引用、允许的保管形式。原字节、提取文本、摘录、元数据和模型转述不能混称原件。

## A.7 内部议程、Watch 与人工确认

内部议程引用案例／假设、重要变量、待取得的证据、可能复核时点及原任务范围，默认不增加外发。Watch 另声明必要数据、触发条件、允许效果、启用依据、结束规则；无数据为无法判断，不填 false。

打开页面或链接不确认；草稿重要内容变化后旧批准不可复用；合法重复确认可对账。原确认、修订与撤回形成关系，不从技术写成功推断买卖成交。原范围语义可继承，新确认凭据的真实性和拒绝行为必须在该能力上线前验证。
