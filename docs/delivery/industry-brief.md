# 产业系列进入同一 Brief

责任：#13。扩展现役 `brief_delivery`、`news-rolling.yml` 的 `desk/read-desk` 和原 Artifact writer；不另建简报库、当前指针、来源缓存服务或研究任务。原 `dos2-news-edition-v1/v2` 字节及读取继续；有 `industry` 才生成 v3，可与原 `research` 并存。

## 精确采用与前版

在原新闻计划中加一个可选字段（引用须替换为实际完整 SourceRef）：

```json
{"industry":{"items":[{"reference":"实际整包 SourceRef 对象","view":"industry","series_id":"实际系列 ID"}],"max_items":3}}
```

`view` 为 `industry`、`operating-cycle` 或 `vehicle-flows`。只接受整包根和已存在的系列 ID，不接受调用者提供的数值、正文、URL、公司净受益或执行代码。经营周期选择原 metrics 中的 `series_id`，不冒作公司映射或采用其全部派生快照。一个选项表示该包中这个系列的**全部原观察点**、原变化或拒绝原因，以及本视图输出的相依历史角色。来源的无关全市场实体字典不复制；精确行/段引用、口径、时间及全部限制保留。

原读取器及 `industry_source_scope` 拥有源核验和算术。Brief 不重求变化、累计相减、库存、现金流或净暴露，不把系列数当商品覆盖数。允许局部可读系列，但原缺点、失败原因、整包 partial、关系拒绝和未知量仍在；零可读点或找不到系列不可采用。相关发行人角色只是原视图事实与假设，历史适用期不升级当前。

`baseline` 继续是上一份**实际已保存**的原 ArtifactRef。先读回原正文、核原新闻及扩展，再比较确切包/视图/系列。身份不含可达 commit，防止同一不可变内容因换提交再次冒作新选择；包内容或所选系列改变会成为另一个选择，不承诺跨包经济事实去重。

确定次序为输入声明顺序，最多采用 `max_items` 个；这不是用户接受或经济排序。分别记录：上一版已采用同选择、此前可读未采用、迟到进入本次交付、新保管的包选择、容量省略、不可读/超出截止，以及不再被选择的前版项目。迟到使用包的实际保管时刻，**不是事实发生、公告发布时间或当前市场时点**。去重仅比较紧邻的实际前版，不建立永久阅读历史；隔一版重新出现仍可能采用。已追踪产业不得静默删去 `industry` 字段；明确空 `items` 才记录退出范围，不称市场无变化。

## 保存、公开与读回

原 `desk` 构建/保存路径、`read-desk` 精确读取路径不变。公共宿主新增 `public_sources_custody_confirmed=true`，研究、新闻元数据及私人反馈许可不能替代产业来源输出权利。构建时在 Store/产物创建前拒绝未确认输入；打开已存 v3 时，在完成原档识别后、正文/JSON/页面导出前检查，不把报告失败当空成功。`reading-room` 打开含产业的指定 Brief 也复用此来源确认；未确认返回 `sources-permission-required` 且整个简报面板不导出。确认字段仅是调用声明，不认证权利事实或人的身份。

使用原 `code_sha`、当前 `main`、稳定 submission 与 records 的 expected_head；一次保存只产生同一个 edition Artifact。未知写继续以原 `result/inputs.json` 调用 `reconcile-artifact`，不重发意图；`read-desk` 不带写入字段。新闻/研究/产业在同一份正文保管，不把已读产业页当 Brief 已采用。独立读回须核原 JSON/正文摘要和字节，再用原 ArtifactRef 生成后继；后继只生成而未保存时不能当下一份已存基线。

原页面继续完整正文下载和本地请求导出；不自动提交、不监听聊天、不发通知。原文通过 literal-text/CSP 显示，源中HTML和指令不执行。Actions产物是传输，不替代原 records 或长期独立备份。

## 有限资源、测试与退出

单次计划最多8个系列选择、4个根/视图组合；每个原结果最多2MiB，每个系列上下文24KiB、产业结构部分96KiB。相同根/视图仅在本次读取内复用；失败不建立永久缓存。超限整项省略并保留精确 item/error，不截断来源或正文。原256KiB edition、60KiB输入、512请求、8MiB页面和阅读室总体预算不提高。组合全文超限仍由原 owner 明确拒绝，不增上限或丢弃限制求绿。

专属验证涵盖原系列/历史角色、三视图比较语义、前版实际采用与容量、可达提交身份、空范围、缺源/未来/上限、重封伪改拒绝、来源许可、原CAS丢ACK对账、v1/v2兼容及原唯一 cold-wheel 两进程消费。合成工程测试、现场读取、真正研究采用、原件真实性与人工接受分别成立。

维护者负责 `application/brief_industry.py`、原简报/宿主和专属测试。退出生成能力时同一普通PR移除可选计划/工作流输入/新生成及专属消费者，但仍需保留历史v3的有权限读取和原引用；退出历史读取支持需另行完成可用迁移，不能因撤销UI丢弃已保存简报。原新闻/研究/Store及共享CI保护不退出。
