# 原问题复核：相邻研究版本与实际简报行段覆盖

责任：#13。可选 `review` 面板复用原 ReadingRoom，不增加 Review 数据库、研究写入入口、更正登记或人工接受记录。已有工作底稿拥有判断与挑战，Agenda 拥有已提交反馈，Brief 拥有实际采用；本入口只把这些确切记录连接起来供复核。

## 使用范围与输入

在原 `reading-room` 的 `plan` 中添加 `review`。它包含 `before`、`after`、`question_id` 和可省略的 `evidence_limit`（默认 2）。前后项都使用现役 Brief 的 `{reference, start, end}` 格式：完整研究 BlobRef、从 1 开始且包含两端的正文行号，每段最多 80 行、8192 字节。不能用公司名、当前指针、网址或正文中的指令替代引用。所选段落与原问题的语义关联由调用者核对，程序不自动判定。

`after` 必须实际记录 `before` 为直接前驱，且为同一案例；`question_id` 必须存在于原结构化底稿。跨多版复核分成相邻对，不自动跨越中间稿。普通非结构化报告、错版、缺失或损坏明确显示不可复核，不猜问题，也不换成当前版。当前研究提交入口原有的原问题与未解挑战保留校验不变。

仍使用原 CLI：

```bash
decision-os store --path /tmp/existing-synthetic.git research-room \
  --input /tmp/review-plan.json --out /tmp/new-review-room.html
```

`review-plan.json` 是完整原阅读计划，额外带上述 `review` 对象；`agenda` 和 `brief` 继续在计划顶层使用各自完整 ArtifactRef。目录、可选完整原文、材料与复核面板的引用可以各自不同，但明确显示各自范围，不把前后两稿计入目录案例分母。

公共宿主仍为同一 `research-runtime.yml` / `operation=reading-room`，新核 `main/code_sha`，`submission_id/expected_head` 留空。因为复核会读来源表示，除原 `public_research_custody_confirmed` 外还必须明确 `public_material_custody_confirmed=true`；省略、字符串或 false 在 Store 访问和公共输入产物生成前拒绝。保存过的议程/反馈仍需原独立反馈许可。布尔字段是调用者对实际授权的声明，不是材料或用户身份认证。

## 四种不同事实

**提出复核。** 仅从指定已存 Agenda 的完整原版引用与原问题匹配反馈；可使用原有整版选择作为默认。无议程、不匹配和不可读分别表达。反馈记录时刻晚于新版保存时刻时标成事后记录；即使更早也不证明它导致修订。反馈是已提交声明，不等于已执行或人工接受。

**实际修订。** 两侧显示原委托、问题、判断、挑战、原文片段与摘要、未决项、停止原因、来源变更和限制。问题改变、委托改变、缺失原未解挑战显式保留，不能用新版省略某项推定解决。`finding_changed`、`selected_text_changed` 只是结构/文字对照，不是判断改进或独立经济复核。Quick/Full 类型变动单独显示；不同类型不赋予完成认证。

**简报行段采用。** 读取同一页面已按原 owner 独立重建的已存 Brief，而不是用户粘贴的计划。只有完整研究引用匹配且该行处于实际 included 集合，才认定此指定简报采用了该版。再检查所选正文行段与实际引用范围的交集，并逐字节核对重叠原文，返回完整、部分或不在引用范围，以及明确未覆盖行段。原版采用不能自动延伸到新版；列入范围但省略不算采用；简报缺失/无权时关系未知，不填 false 代替未知。

覆盖仅指所选**正文行段**。相同观点可能在简报的其他判断/上下文里表达，因此未覆盖不自动等于语义更正完全缺席；覆盖也不等于更正内容正确。此版与另一版 Brief 分别核，不自动认定最新或扫描全部历史。实际传递更正仍沿既有 Brief 的显式构建、保管与独立读回，不因本次阅读自动发版。

**人工接受。** 本入口始终 `human_acceptance=not-established`，不接受调用者塞入 `actor=human`、`accepted=true` 等授权/结论字段。用户或研究者的实质解释与其权限要另有真实依据；程序比较、CI、浏览和下载均不代签人工 Decision。

## 来源、失败与预算

每侧只沿所选问题 finding/challenge 的原来源下标并集，实际读取最前 1—4 项；其他相关引用保留为未读请求。保持 SourceRef 的行/列选择、原下标与 Reader 的原件/表示/外部定位/缺失状态，来源数量不是独立证据数；external-only 不触发补抓。同一次来源在两稿各被引用不表示两个独立事实。未附证据明确为零项声明，不构成充分性认证。

单项来源显示 64KiB，超限整项省略 view 并保留状态、精确引用和原读取请求；复核面板 768KiB，超限整个面板不展示，不截断原文。来源缺失、未读、超限和原问题/未解挑战未保留使面板 partial，原研究与其他合格面板仍可读。全局目录或最后访问权限检查失败则整体拒绝导出。原 6MiB 模型、8MiB HTML/宿主输出、512 请求以及来源预算保持，不增加/重置额度。

`readable` 只表示所需记录在本边界内可读取；并不证明挑战已解决、证据原件可信或整个研究完成。两稿保持原始字节，由原 Store/Artifact 通路负责保管；页面无自动网络、活动 HTML 或新写入，只使用已评估的标准 DOM/textContent、CSP 摘要和标准库。退役用普通 PR 移除 review 计划、展示与专属测试，原问题、研究版本、来源、Agenda 和 Brief 历史读取责任继续。

专属测试沿原真实临时 Git、原宿主 API 模型与原唯一安装后消费者，覆盖同版但错段、部分交集、真实省略、前后版本、坏来源、问题/挑战保留、权限、预算和独立重开。合成测试不替代真实问题的实质复核、人工接受、来源原件认证或生产运行；现场采用须另核原生输入、结果、字节和解释。
