# 多对话交接：短记录、真实接点

统一规则见 [WORKING-PROTOCOLS](../../WORKING-PROTOCOLS.md#collaboration)。此处只有可复制格式和异常路径，不另建进度库、心跳服务或会话注册中心。

<a id="start"></a>
## 1. 新会话开始

从仓库URL就能开始；先解析当前main并读AGENTS→#3→具体任务。用户已经给过的范围/选择不重问，最新明确且仍有效的授权继续适用。读取当前任务的必要评论、PR diff/head、已合并项及实际检查，避免照旧摘要重复施工。

在任务当前接点写入并读回以下短记录；不存在原生会话ID可用实际分支+描述，不发明平台ID。

```text
认领/接管：职责、会话描述；原owner交接/用户分配依据
任务与范围：Issue；做什么、不做什么
基线与分支：实际main SHA；分支；当前head；已有PR
共同规则：本次实际读取的main及适用文件；关键已验条目
并行冲突：共享文件/接口；其他活动PR；怎样避让或交接
下一动作与停止条件：一个具体动作；权限/未知效果等限制
```

写认领不是锁。提交前/合并前再次读分支；出现另一owner或未知head先停止该写入。别人的PR只读审阅，不在未经交接时追加提交。

<a id="finish"></a>
## 2. 暂停或结束

将下列内容保留在**当前有限任务的评论**，正文只更新短摘要和精确回执链接。没有实质新状态不重复发相同交接；完整日志放原产物，不粘贴全过程。

```text
目标/授权：本次完成的范围；没有扩大哪些权限
实际位置：branch / head / PR；base；已合并main（若实际发生）
成果：已提交可读回；未提交/未上传的具体部分及能否恢复
验证：实际命令/原生run/范围/结果；未执行的明确写未执行
未知效果：已发请求/写入/运行的定位，已确认与未确认分别写
接续：具体剩余责任、下一动作、依赖和停止条件
资源/认领：已释放或仍在途；下一会话是否获准接管
```

同一会话不能签“独立新对话恢复通过”。本地文件没有远端保存就标本地；未提交字节无法从Git恢复，不用一份口头摘要代替它。

<a id="recovery"></a>
## 3. 异常恢复

| 现象 | 先做什么 | 不能做什么 |
|---|---|---|
| 旧下一步已被后继PR完成 | 核main/PR/验收后转实际剩余责任 | 按旧聊天重新实现 |
| 分支存在但无最新交接 | 读原提交/diff/检查/原任务范围，恢复已知部分 | 假称全部本地工作已恢复 |
| 写入超时/无响应 | 按原提交键/目标/head查实际效果 | 换标题/key/目的地重发 |
| 明确权限拒绝 | 保留具体动作/目标/错误，停相应操作 | 换身份/HTTP包装绕过 |
| 两个会话同时认领 | 对账实际head/PR和用户分配，只保一个writer | 最后写入者自认获胜、删对方分支 |
| 规则在工作期间更新 | 读取相关差异并重新核受影响检查 | 用旧规则提交或全仓无限复习 |
| 任务已合并但未产品验收 | 保留phase:verify和缺口，按实际验收继续 | 自动关闭产品Issue或重写已合并代码 |
| 已暂缓/停止的旧路径 | 保留原因，等明确恢复 | 根据更新时间/期限自动激活 |

## 4. 无需用户反复搬运的接续提示

用户通常只需给出仓库和“继续”。对话应自行完成上面的读取与对账。可用的简短启动语为：

> 从 auguspp/Decision-OS-2 当前 main 的 AGENTS.md、阶段导航和实际 Issue/PR 恢复，按统一协议接续当前已授权责任；不重做已完成工作，不沿旧 Kernel 队列施工。

这句话不是新权限来源，也不保证宿主自动加载文件。实际读取失败时报告缺口并使用仍获准的可用工具；不要先宣称系统没有读写能力。

## 5. 本批与第一次后继

#4交付规则、模板和可定位入口，检查的是文档结构与恢复路线可读性。下一次真实独立施工会话在其正常任务留一条认领/恢复记录，即可证明该次入口使用；无需为独立验收额外重跑Quick/Full或造同形任务。
