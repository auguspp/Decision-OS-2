## 1. 本次对账结论：主要遗漏在“目标到施工”的映射

v0.1明确了工程骨架、保管、双核心和后续条件判断，但把多条雷达压缩为“最小Radar”，又把界面、复盘等笼统归入后期。目标稿往往已有对应责任，问题是实施者缺少明确的交付位置。

| 被遗漏或弱化的责任 | 原来容易发生什么 | 本稿修正 |
|---|---|---|
| 行业、概念、独立个股三条市场发现 | 一个行业榜单代签全部市场雷达 | 独立列出三种用途、旧起点、来源与完成边界 |
| 产业基本面与商品价格×公司暴露 | 只接一条涨价新闻，把公司映射和其他产业族留到“以后” | 有限商品首个切片就含双向、有证据的公司关系；扩数量与建经济联系分开 |
| 聪明钱的多维公开参与者行为 | 龙虎榜或一份研报被算成整个聪明钱完成 | 八个观察面逐项保留；首发选真实可用用途，其他面有明确后继 |
| 全球背景、新闻/叙事、公司与宏观事件日历 | 只有行情/Quick，没有资料和事件持续进入研究 | 共用输入，分用途推进；背景、计划、实际事件不互相冒充 |
| 公告/财报/财务表、非个股研报、私有研报入口 | 内容池能存但没有研究真正用得上的资料路径 | 资料接收属于#6；来源发现/正文入口明确归属；私有消费不冒称已验 |
| Attention、直接阅读、Quick Inbox与轻量反馈 | 只有Brief，用户看不到未入选内容或无法继续某个问题 | 首发就有公司/问题/来源的可读入口和显式选择，不要求先建复杂页面 |
| 研究日历、Watch、最小Review与更正 | 全部放到Decision或Learning后序 | 研究议程/更正/按需Review早期落实；正式提醒和Decision权限仍独立 |
| 运行宿主、更新健康、备份、故障隔离和切换 | 实现成功后才考虑怎样可靠日常使用 | 与相关输入、保管、交付同组建设；首次生产前具备所需保障 |
| 多期限表达、竞价/盘中/价格结构、外围创作 | 要么遗漏，要么从旧登记直接自动启动 | 日频表达先复用；盘中/竞价/Chan/Wyckoff明确后序；外围创作不默认迁入 |

以上是施工缺口，不是九个新平台。成熟责任由已有实现/方法承担，新工程集中在引用、接收、用途资格、真实消费者和必要权限边界。

## 2. 已确定的方向与本次不变项

- 唯一项目代码与规范仓：`auguspp/Decision-OS-2`。分发名 `decision-os-2`、导入包 `decision_kernel`、拟CLI `decision-os`，不保证旧API/CLI兼容。
- Quick/Full是首版双核心；定时Quick与交互Full由获准AI宿主执行，WorkBuddy等成熟工作台优先，现役GPT任务在切换验收前保持原责任。Full可直接委托，不必先Quick；不另建第二后台AI平台。Decision完整设计、专门建设较晚；无个人持仓、账户同步、仓位或自动交易。
- 来源按用途适配，A股日线现役主源沿[FTShare合同](sources/ftshare-daily.md)，其他Relay用途及历史保持，不恢复多行情提供方fallback。允许少量成熟、用途明确的常驻内容源；研究期取证、被引证据固定与机械扫描分别验收，未核连接器不自动成为生产源。
- 完整CI优化体系从首个代码组交付：四scope、合同小环境、跨runner/片内worker并行、身份/集合/环境核验、严格merge_reuse。不得借此次重排后置。
- PIT按用途，Learning先按需Review；不兼容旧Kernel/OS研究、旧概率、旧接受与旧运行环境，不默认迁移旧数据。
- 既有GitHub研究通路、Full方法、算术和原范围验收继续复用；只验新合同/目标/存储/权限/消费者。58项对账仍为21继承/19差异/7新增/4未证实/7取消，不重分、不转为完成率。
- 现有资源可用，费用不构成阻塞；仍遵守实际访问、来源权利、限流、隐私和安全。研究议程在原委托内接续，保存成果不自动开启新Full、任务、主动通知或投资决定。
- 后续用户已在[#6采纳路线A](https://github.com/auguspp/Decision-OS-2/issues/6#issuecomment-6187561836)：公开仓 `main` 保持工程专用、独立公开 `records` 分支保管有公开权利的原创研究及来源版本；不再以私有仓库作为首版前置。密钥、个人/第三方隐私、受限原文和正式Decision仍不得公开，公开分支不等于权限隔离。

## 3. 施工模型：阶段负责依赖，产品线负责完整性

### 3.1 保留 B0—B4，不把工作重新编号为另一套工程系统

| 阶段 | 重排后的范围 | 依赖与退出 |
|---|---|---|
| B0 统一基础 | #4已交付；本轮只补实施映射与有限任务，不重做基础规则 | 本稿归档及导航同步是本轮文档范围；不冒称产品已运行 |
| B1 工程入口 | #5最小可安装包＋完整CI＋必要主线设置 | 第一个代码PR正常执行本仓完整验证，不要求预先已有可信full；旧绿灯不代签 |
| B1 共同数据与研究能力 | #6来源接收、版本、最小主体身份、查询/引用、研究保存、权限与恢复 | 建必要可用部分即可向B2提供合同；不要求所有来源/全部数据库/全量索引完成 |
| B2 首发并行 | 市场雷达；产业商品/公司联系；披露与参与者资料；Quick/直接Full；日常阅读/议程/Brief及运行保障 | 各线按必要产物推进，Full不排在雷达全部完成之后；首发验收不得遗漏真实发现与Full |
| B2 雷达后继 | 补齐已保留的各雷达观察面、全球背景及资料入口的声明范围 | 不等Decision建完，不把它们统称B4“可有可无”；每组有限收口，未交付维度留下准确后继 |
| B3 条件判断 | 条件计算/概率Odds适配、多期限Opportunity、获准Watch、正式人工Decision | 依赖合格研究和输入，不依赖所有雷达覆盖；可与B2后继并行 |
| B4 按需扩规模/深化 | 商品族到500+的合格覆盖、更多地区/关系、专项Review与界面深化；明确的盘中等增强 | 根据实际用途与来源资格扩展，不复活全局PIT/自进化/旧兼容 |

“B2首发”和“B2雷达后继”只是交付范围的区分，不新增运行状态机或审批层。#3仍只承担有限B0—B2首发导航；其关闭不表示全部雷达目标完成，关闭时必须将未完成的有限范围移交具名后继，不能藏在已关闭父项。

### 3.2 依赖图

```text
已完成统一基础 #4
        ↓
可安装骨架＋完整CI #5
        ↓
最小来源/研究保管 #6 ── 必要合同可用即释放消费者，不等全量完成
        ├── 直接Full与Quick研究能力 #7
        ├── 市场雷达：行业／概念／独立个股 #10
        ├── 产业与商品：变化 ↔ 公司经营暴露 #11
        └── 披露与参与者：财报／研报／事件／公开资本行为 #12
                  ↓ 这些线按真实依赖相互消费，不能串成全局门槛
        直接阅读＋Attention＋研究议程＋Brief＋正常运行与反馈 #13
                  ↓
        首个双核心可用产品（#7集成验收，#3有限阶段收口）
                  ├── 已保留雷达观察面继续补齐
                  └── 计算适配／Opportunity／Watch／人工Decision
                              ↓
                       按需扩覆盖与Review深化
```

资料和研究方法的只读准备可以与#5并行；代码合入依赖相应工程能力；实际持久写入依赖获准目标、内容公开权利与可信writer；受限私人材料仍需要合格私有目标。定时/外发/切换依赖各自真实授权。不能把“某Issue还没关”当作它所有产物都不可用，也不能把有产物等同于已有运行授权。

### 3.3 不是把所有雷达重建成完整独立流水线

共用来源取得、版本保管、主体识别、检索、引用与交付。雷达只拥有自身用途所需的比较、异常、状态与缺失解释。Quick解释和调查，Full深入研究；用户可直接阅读雷达，不必先经过AI总结。

同一份公告可以供资本行为观察、研究反证和事件日历使用，但只保管一个真实来源版本。不同来源族不能被统一成同一种恢复、交易日或报价口径。替换来源时保留语义，不能因字段同名或旧算法通过就宣称新来源适配已通过。

### 3.4 架构收敛从现有接收能力开始

自建保留稳定内核、版本化方法和必要连接层；外围信息取得、AI研究执行与交互优先复用。业务入口复用[现有操作映射](research/runtime.md#kernel-operations)，业务能力的输入、消费者、责任与退出条件维护在[原交付入口清单](architecture/workflow-estate.md#business-responsibilities)，不再建总设计或进度账。

先同步合同和操作，再交付一个受信版本化外部研究合同的接收切片，随后用有权限的真实来源和后继研究完成宿主采用，最后退出已有替代者的旧业务责任。普通 `RevisionInput`／`VersionedStore` 已可保存部分成果；后续解耦的是默认方法选择及其执行核查，不重建保存引擎。方法替换不能抹掉未决问题，也不自动取得经济充分性、行情／概率或人工确认资格。

运行恢复与接收侧离线工程可按文件和副作用分工并行，共享接口由一个集成人串行合并。单一权威、受控写入、幂等／CAS、时间与来源用途、未知效果对账和Human边界必须保持；GitHub运行器、具体供应商和工作台是当前部署选择。没有等价接收与独立恢复证据前保持现役部署，不借此启用暂停Watch、扩来源预算或创建新私人Decision载体。完整人工确认沿既有B3责任专门建设，不阻断普通研究使用，也不能在架构收敛关单时丢失归属。

## 5. 雷达完整范围与分期：不再只写“最小Radar”

### 5.1 市场/概念/个股

三者共用合格行情、必要分类与日历，但不共用一个准入门。行业或概念未触发，不阻止独立个股发现；股价变化不是经济机制证据。页面首屏可有限，已取得的声明范围仍可检索/按窗口浏览。

首发优先沿已验证日频用途，声明5/20/60等实际支持窗口及缺口；不足窗口只影响该用途。主题/行业成员变化、新分类来源与复权规则必须对账；现役适配不支持某分类时明确该维度未接入，不能偷偷恢复另一行情底座。

### 5.2 产业与商品价格

保留需求/新订单、生产、库存/资金占用、利润、汽车产批零出口、生产资料、物流/运价、存储报价等原产品面。首个周期贯穿样例必须既有合格变化，也有发行人依据支持的公司角色；不要求第一天形成精确盈利弹性。

商品面要包括上涨、下跌、持续变化、价差/成本与可能拐点。化工、猪/鸡/蛋/饲料、航线运价、能源金属建材、电子/存储与新能源等按真实可用来源分批；目标商品名、合格可比系列、实际新鲜监测数分开。500+是后续量化覆盖里程碑，不是首发前置，也不是填名称的配额。

商品→公司与公司→售价/投入/运费两向查询在首个真实切片同时成立。关系层级保留：候选联系；证据支持的经营角色；数据足以形成有边界敏感性。未知占比、传导率和时滞不得填0或默认100%；上下游、替代、库存、套保和一体化可能抵消影响。

旧#864在旧仓的暂缓记录保留为历史，不自动启动原采集。新项目已决定分期纳入能力；本稿仅排计划，不激活常驻抓取，也不把旧一次乙腈报价取得当作持续采集许可。

### 5.3 聪明钱与公开参与者：八面都要有处置

| 观察面 | 保留的产品责任 | 不能冒充 |
|---|---|---|
| 游资/公开营业部轨迹 | 原标签、席位、证券、窗口和买卖事实可检索 | 供应商别名不是本人认证；重叠窗口不相加 |
| 机构席位 | 上榜机构买卖及数量，独立于Sector强弱门槛 | 某基金全账户、完整仓位 |
| 北向公开数据 | 各渠道及持股披露按实际现行字段和频率 | 每日个股净买/实时仓位；成交额不等于净额 |
| 股东/基金/具名个人 | 报告期、证券/股类与持有人身份可比，公司/参与者两向检索 | 同名必然同人，榜单消失必然清仓 |
| 机构调研 | 公司、活动、披露文件和参与者分开统计 | 一场100参与行等于100场活动 |
| 研报与可比预期修订 | 同机构/指标/目标年/口径有依据的比较 | 不同机构分歧直接算同一预测修订或全市场共识 |

首发按已存在合格用途先交付；其余面进入同一有限雷达后继，不等待正式Decision。每面说明声明范围、实际可用、缺口和后继，不能一个可用面关闭“完整聪明钱”。旧八面合同提供语义，不授权照搬旧供应商、抓取频率或费用限制；市场与内容来源分别按现役用途合同及替换准入处理。

### 5.4 全球、新闻与事件

全球六族首先服务跨市场变量到公司经济的解释，不要求一次覆盖所有市场。新闻/RSS、研报目录和公开叙事为不同资料入口，共用保管与去重，事实、观点和转载关系分开。

事件日历不能只存“哪天发新闻”：公司财报预约、改期、实际披露、分红/解禁等实施日期，以及宏观/产业事件按实际证据记录。Full的重要验证窗口进入内部议程，即使当天没有新闻推送也能在正常后继中看见“到期未取得材料”。这不自动新增提醒任务。

## 7. 共同接线与保管边界

来源更新频率来自各自用途，不机械全设每天。日历/市场日、报告期/披露日、取得时间和实际任务结果分开。共用客户端/速率预算的实际owner明确，可选源失败不吞兄弟能力，落盘失败阻断相依推进。

首次实际持久写入前核获准目标与内容公开权利（受限材料须独立受控）；首次采用新存储时验证相应提交/恢复；首次清理前明确保留期和引用保护；首次定时或新旧切换前明确writer、最后有效产物、在途/未知效果、退回路径及授权。无需为尚未采用的介质预建平台。

健康至少说明最近尝试、最后合格结果、实际资料日期/范围、待交付与备份状态。没有配置/没有执行/失败/已完成零变化分开。新系统切换不默认停旧任务，不在未授权时双重采集，也不因费用可用无限重试。

CI、实际服务、来源、GPT研究、Brief和通知分别维护其运行身份与权限；工程写权限不下放为研究任务的系统管理权。没有强隔离就如实说明，高影响功能不能假装安全上线。
