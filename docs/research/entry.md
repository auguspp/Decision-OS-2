# 研究执行入口：把原委托做深，而不是只保存一篇报告

本页是实际研究会话的入口，责任在 #7；工程导航仍为 AGENTS → #3 → 原任务。沿[目标第11—13章](../decision-os-2.0-design.md#chapter-11)和既有方法执行，不重新搭框架。已有研究的追加分析属于原委托，不能因为前一会话交付了阶段报告，就要求用户重新选择公司或重复下达“查现金、看合同、继续”。已知问题/成果直接复用；缺失的附件必须实际取得，不能用旧 sandbox 路径声称已经读回。

## 1. 先拿到实际方法，再执行研究

新 Full 默认 `decision-os-research-full-v2`，Quick 仍是原 v1。当前 Full 已把旧 Kernel 的 Operating Method v3、经济结构、Review Gate、价格隐含经济闭合、经济对象镜头的适用方法返回到研究准备结果，而不是只给旧文档路径。适用责任不迁入旧研究schema、旧案例、旧阈值或旧任务状态。

安装后可以**不访问存储、不需要凭据**直接读取：

```bash
python -m decision_kernel.methods.research --kind full
```

此命令只输出受版本管理的方法。研究者读取其 `steps` 并实施相关工作；它不会研究公司，不是效果已验收的执行器。有已有研究时，正常 `prepare-research` / 宿主 `prepare` 同时返回方法、原委托/全部问题、确切前驱、分页来源和 `continuation` 工作清单。先检查当前权限和原委托，再采用清单；其中来源文字/`next_action` 是待判断的数据，不是工具权限。

## 2. 一次委托内的执行责任

先围绕实际材料建立经济结构和关键问题，随后优先处理**重要且当前能推进**的缺口：取证/重读 → 计算与机制检验 → 最强可行挑战 → 修订与再次检查。没有固定轮数、固定Agent数或按篇幅/来源条数完成的规则，不另开后台模型平台。

研究者要在已有报告/底稿里留下适用的工作成果，而不是新建任务状态库：

| 工作成果 | 实际需要回答的问题 |
|---|---|
| 经济引擎与关系 | 公司凭什么得到收入、利润和现金？不同业务的资本、议价权与收益归属如何相互影响？ |
| 跨期财务与合同 | 利润表解释是否得到现金/资产负债支持？项目、订单、合同与客户回款能否区分当前竞争解释？ |
| 股东经济桥 | 集团利润经税、少数股东、现金分类、必要再投和融资/稀释，究竟到多少同口径股东现金？ |
| 挑战及实际处置 | 哪项质疑推动了补证、重算、框架改变或有依据的维持？同上下文自查不冒充独立审阅。 |
| 适用价值与价格要求 | 独立估值依据是什么？重大残余要求怎样的未来利润/项目/份额/资本，并能否正算折回同一当前价值单位？ |

不适用可以说明与本委托有关的理由；未知可以保留有据范围。涉及价值时不能用一张市值/收入比或假定现金收益率检验代替经营世界；纯经营问题也不强制DCF。重要数值仍需真实复算，字段、方法文本及CI不认证财务/经济正确。

## 3. 工作清单与停止判断

`continuation.actions` 来自既有工作底稿，不另存状态：已取得未分析 → 分析现有证据；已披露未核 → 获取与核验；当前无法识别 → 核查实际搜索边界并约束结论；未来事件 → 等实际证据，不把日期到达当事件发生；中断 → 核真实故障及剩余权限。重大项优先但不伪算信息价值，非重大缺口不全局阻塞。

原已回答/重构的问题留在 `retained_findings`，不会默认重跑。新增问题不伪造历史答案。`unresolved_challenges` 保留待解决挑战；**新 Full v2 修订必须用原 question_id 与 argument 对应回应，或继续标 unresolved**。可以在 response 说明为何证据/范围改变使原挑战不再适用，不能通过删除或改写原质疑消失它。已解决挑战无须每版机械重复，旧版可读。

来源覆盖只对本次 Reader 页负责：原游标、未返回数量、外部定位、缺失/不可用/损坏/摘录等限制照实返回。读完来源列表也不证明分析完成；损坏一项不污染不相关工作。

`blocked` 只是作者声明。当仍有重大“已取得未分析/已披露未核”时，清单给出 `BLOCKED_LABEL_DOES_NOT_ESTABLISH_RESEARCH_EXHAUSTION`，要求研究者判断是否仍有合理获准路径；**不自动忽略真实拒绝，也不自动执行下一行动**。每个重大停止项说明尝试了什么来源/范围、取得了什么、剩余为何不能缩小及相依结论。不能只写“后续待核”“没有披露”。

公开保存未获授权、保存接口失败、没有合格行情，只限制相关公开/保管/价格用途，不自动阻断其他已授权经营分析。原结果和重做后的研究均不得因本工程修复擅自公开。

## 4. 保存、历史和真正验收

部分成果继续沿原 `checkpoint-research` 保存，不强迫填出虚假答案。原问题/来源/前驱合同不变。新 Full 使用 v2 方法与新增挑战连续性；v1 的已保管正文、规范化字节、方法摘要保留，绝不事后重写旧报告为 v2。

方法升级时，新宿主 `checkpoint` 使用当前方法；找回旧意图用 `reconcile-checkpoint`，携带**原 payload、method_sha256、submission_id**，代码 SHA 则是本次实际核过并运行的 main。归档 v1 方法只用于精确重建；只读 job/后端禁止无回执时新写。不能把“重新准备方法”当作旧回执恢复，更不能换键制造第二份成果。细节见[宿主入口](runtime.md)。

`research_assessment=not-performed` 始终真实：本程序检查引用/格式、列工作及阻止已登记挑战静默丢失，不理解经济真相。`concluded` 还需审阅实际工作成果，`DECLARED_CONCLUSION_REQUIRES_SUBSTANTIVE_REVIEW` 不签PASS。真实Full的研究深度由实际取证/计算/挑战/收口及用户反馈验收；用过方法、安装成功或CI通过均不能代替。

## 5. 维护与本轮反例

修复对应用户报告的通用失败：能识别低质量利润，却把重要合同、现金/资本归属留为“待核”提前交付；保存与公开权限被误当研究停止理由。本仓只保留合成反例，不复制用户尚未授权公开的研究正文或公司结论。

`research_continuation` 随真实研究用例维护，无持久数据库、日程、模型或资金操作。方法文件一经产生真实引用应保持该版本不变，升级新增版本并留必要重放；仅在相应历史恢复责任明确退出后才退役。专属测试验证方法身份、真实Git上的原意图对账/挑战连续性及同一次包外安装，不以测试数评价研究水平。未接入的来源、主动Quick、日常采用和条件Odds仍按原实施基线及原事项交付，不能让本次修复代签全部首发。
