# Relay 主营构成：原行、抵销与财表对账

本用途把现役 `fina_mainbz` 已捕获结果交给真正的经营读取器，而不是再建立
一个取数器。`application.main_business.read_main_business` 复用
`research_sources.inspect_result`、`FinancialQuery`、原财务单元格解释和 Decimal。
原来源获取、失败恢复、Secret、公开授权、SourceRef/Store、研究与 Brief 各归原 owner。

## 范围及来源依据

2026-10-17核对的[Tushare官方主营业务构成合同](https://tushare.pro/document/2?doc_id=81)
规定 P/D/I 为产品/地区/行业维度，`bz_sales/bz_cost/bz_profit` 按元表达，
`curr_type` 保留币种，`update_flag` 只是更新标记。原[八财务合同](relay-financial-batch.md)
仍拥有底层字段解释。接口说明不证明实际 Relay 单位、发行人真实性或历史可知性。

只接受单公司、单报告期、显式单维度和原登记快照的注册捕获。不混合P/D/I；
不跨捕获拼表，不自行用 `fina_mainbz_vip` 替换已保存请求，也不重抓已成功结果。
请求必须明确八个基本字段；`bz_code` 是可选返回核对，旧捕获未请求它时如实标
`request-only`，不伪造返回值。当前只识别 `0/1/null/空字符串` 更新标记；不以其选择最新版本。

## 读取与诊断

- 每行保留原值、币种、更新标记及原查询/页offset/行/时间/投影定位。空、null、零分别保留。
  同一业务标签和币种的重复行全部隔离，即使值相同或标记为1；不first/last取一条。
- 收入减成本只叫 `sales_minus_cost`，另与原 `bz_profit` 作精确一致性核对；
  缺失利润仍缺失，不用相减结果填回它。差值率只有收入>0且成本非负时计算，
  不能把负数抵销项的比率展示成经营毛利率，更不称归母净利率。
- 按币种分别作**所返回行的有符号代数和**。负数保留原符号，不再重复减一次、不绝对值化。
  重复/隔离行或分页未完使合计不可用，不只合计“好行”；单字段缺失只限制该字段。
  即使合计等于报表，也不认证这些行互斥、覆盖完整或可作为业务占比分母。
- 可选一个同公司/报告期、唯一 `report_type=1` 的 income 捕获，分别对照 `revenue`
  和 `oper_cost`，不误用 `total_cogs`、单季或母公司表。仅对唯一CNY构成作原始数值对账，
  控制表沿原 `currency-unit`，没有自动提升为元或同币种/缩放已核；不做汇率转换。控制表缺失、冲突、重复、未完或日期错误只限制对账，保留主营读取。
  两次捕获的同期间与数值相等不证明同修订批次或相同单位，输出永久保留该限制。
  [income官方说明](https://tushare.pro/document/2?doc_id=33)区分营业收入、营业成本与
  营业总成本，但本次读取页面未逐字段标单位；不从数值相等反推单位认证。
- 报告期不能晚于捕获日，捕获不能晚于显式阅读截止；日期不当盘中PIT证据。
  无行是 `empty`，不是公司没有这项业务；条目过滤只改展示，不改整包数量、合计和版本。

数值沿原财务单元格解析；最多64字符、64有效数字和绝对指数64。运算使用独立
256位十进制上下文，不受调用者低精度/舍入/异常陷阱影响，不舍入差异求一致。
原捕获上限16MiB、100页/10000行；这些是读取边界，不是已买接口用量配额。

## 实际使用

直接使用原 `relay_research_cli` 或原宿主已产生的 `capture.jsonl`，不改其原字节：

```bash
python -m decision_kernel.interfaces.main_business_cli \
  --capture /authorized-local/capture.jsonl \
  --ts-code 002714.SZ --period 20260630 --dimension P \
  --as-of 2026-10-17T10:00:00+08:00 --with-income \
  --output /new-local/counts.json
```

默认只输出生成请求key、范围/核对计数和安全状态；不输出业务标签、数值、
响应ID或来源衍生哈希。显式 `--include-values` 才输出本地详细结果，**不授予公开保管权利**。
`--item` 为精确原业务标签过滤。原JSONL至多32MiB/512行，重复JSON key拒绝；
同一查询跨阶段复用须捕获完全相同并逐条通过原检查，不挑选非同一版本。
未选择的其他API失败不影响本用途；命令本身无Secret读取、网络调用或Store写入。

完整主营可读且所请求控制对账matched（或未请求控制）退出0；partial/empty/
对账差异/控制不可用退出2并保留已成功结果。无有效主营、坏输入/无法独占创建输出
则安全拒绝，不覆盖输入或已有输出。默认计数回执不能重建供应商原行或冒充其SourceRef。

## 经营角色与生命周期

主营销售项目不等于采购合同：例如一项原料销售不能证明当前采购数量、库存批次
或套保净头寸。公司采购/生产角色继续按[产业阅读合同](industry-reading.md)的发行人
证据、适用期及四项传导反证建立；本读取器不创建角色、评分、毛利预测或研究版本。
统计旬价不能直接乘本表收入推算利润；当期合同/一体化抵销/现金流仍需其他依据。

本用途没有新增通用平台：现成Tushare字段合同＋现有捕获验证足够承担来源，
标准库精确算术承担窄诊断；额外SDK、图数据库和会计合并引擎没有本组必要消费者。
维护者同步维护应用、离线CLI及 `tests/test_main_business.py`；原唯一冷安装测试调用
本组的包外消费辅助，不新增安装流程。退出时一起移除辅助调用、专属测试并撤导航。
原来源捕获/公开权限/保管/历史Ref和其他产业读取保持。真实资料采用、原件核验、
长期保管、Full经济质量和Brief实际采用分别验收，不以本地或CI合成测试代签。
