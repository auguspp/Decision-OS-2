# 新闻标题：拒绝诊断与有限换行投影

这是[新闻采集入口](news-intake.md)的局部说明，归新闻采集owner维护；不改变SourceInput、24小时窗口、来源资格或公开原文权利。

`source_outcomes[].capture.safe_structure.headline_profile`仅在原失败回执的NewsNow形状中提供有界测量：最多30条，记录非对象行、非字符串标题、空白标题、无法编码UTF-8的标题数、最大原字符数/去首尾空白后的字符数/UTF-8字节数、含控制字符的标题数，以及33种C0/DEL码点的出现次数。不同计数可能描述同一条目，不相加为独立失败数。

测量使用当次实际响应。它不回传标题、URL、任意上游错误、字段值或凭据，不截短/补造标题，不作语义修订。超过30条不做标题剖面；Relay行单元格不在此剖面范围。原响应字节摘要依旧不是可恢复原件。

采集的准入仍由现役`news_windows`校验决定。失败仍保留原错误码及非成功结果，不能根据存在诊断字段就宣称来源恢复。过滤零条时由既有正常阅读入口保留整批回执。只对确需复核的失败来源显式调用，不因为诊断不足重抓成功兄弟来源；不新增调度或自动重试。

本功能与`news_capture`及`tests/test_news_headlines.py`一起维护/退出，既有新闻校验和保管保护继续保留。真实根因取决于实际回执；合成反例和代码CI不替代现场来源证据。

## 已确认的两源LF处理

2026-10-16的定点诊断（#46评论6210746016、原生run38869558140）确认：wallstreetcn的30条中3条标题含18个LF，thepaper的20条中1条含1个LF；无空白/类型/UTF-8问题且长度均在限额内。其他控制码点未见。这是当次有限证据，不代表所有未来标题均如此，也不从诊断重建已丢弃原响应。

`newsnow-lf-to-space-v1`只作用于这两路原生NewsNow适配：逐个U+000A投影为U+0020，保持全部其他字符、不合并空格、不截断、也不把空标题补成有效标题。CR、TAB、NUL、DEL和其他C0仍拒绝；长度/UTF-8/URL白名单继续检查。其他五路NewsNow、Relay以及已保存行的严格校验不扩大。不能对历史失败字节就地修补后标成旧时点成功；新请求是新观察。

原始标题仍参与原版次指纹，因此原换行和原空格标题即便显示相同，也不会静默合并为同一版本；原本无需投影的标题保留旧版本算法和完整行形状。有效源结果只在确有改变时增加`headline_projection`，包含固定policy、changed_titles和raw_titles_retained=false。该字段由既有combine进入整批source_outcomes，并在普通read/export与24小时窗口的全窗健康中保留；语义不因筛选为零而消失。

保存的是可读单行标题的观察表示，不是原始标题字节或媒体全文。原响应/标题指纹不能替代原文恢复，也不认证新闻事实。投影说明保存在批次结果而非另建来源表；外部SourceInput定位仍是外部定位。未触发投影的历史成功视图不改字节、不重新编号，已存旧失败也不删除。

局部投影及tests/test_newsnow_linebreaks.py由新闻观察owner随现役消费者维护；退出时须同时考虑已存派生标题/批次元数据的读取支持，不能删除旧来源来回退。诊断、合成回归、正式CI和真实两源恢复/保管分别验收，不从代码通过推定现场恢复。
